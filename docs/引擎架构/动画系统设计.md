# 动画系统设计

更新时间：2026-07-30

本文记录 Wheatear 动画系统的正式方向：动画不是某一个玩法模块的附属品，而是引擎级通用能力。VN、横板战斗、回合制战斗、UI、后续地图/图鉴/任务等系统都应该通过同一套动画数据、事件和命令机制协作。

## 1. 设计目标

- 通用：同一套 `SpriteAnimatorComponent + AnimationClip + AnimationSystem` 能服务角色、怪物、技能特效、UI 面板、VN 表情切换和回合制演出。
- 数据化：动画 Clip、帧、UV、属性轨道和事件都序列化到 `.wt` 场景或 prefab 中，避免把动画流程硬编码到玩法模块。
- 编辑器友好：策划或美术可以在 `Animation Editor` 中创建 Clip、生成 spritesheet 帧、拖动时间轴、添加事件和预览效果。
- 可协作：动画事件通过 `CommandBus` 执行命令，可以触发 `.wts` 事件脚本、播放其他动画、切换状态、播放音效或通知玩法系统。
- 高性能：正式资源优先使用 spritesheet / atlas，一张纹理配多段 UV 帧，减少逐帧换贴图造成的状态切换和资源管理成本。

## 2. 核心结构

### 2.1 AnimationFrame

`AnimationFrame` 表示一个序列帧：

- `Texture`：帧使用的贴图。推荐多帧共用同一张 spritesheet。
- `TexCoordMin / TexCoordMax`：当前帧在贴图中的 UV 区域。
- `Duration`：帧持续时间。

逐帧独立 PNG 仍然能用，但正式资源建议打成 atlas。这样人物 `idle / run / attack / hurt` 可以共用一张或少数几张图集。

### 2.2 AnimationClip

`AnimationClip` 是一个完整动作：

- `Name`：例如 `idle`、`run`、`attack_1`、`air_kick`、`ui_open`。
- `Looping`：是否循环。
- `Frames`：Sprite 序列帧。
- `PropertyTracks`：属性动画轨道，例如透明度、颜色、位置、缩放。
- `Events`：动画事件轨道，用来在指定时间触发命令。

`GetTotalDuration()` 会综合帧长度、属性轨道长度和事件时间，确保纯事件动画或纯属性动画也有正确时长。

### 2.3 SpriteAnimatorComponent

实体挂上 `SpriteAnimatorComponent` 后就拥有动画能力：

- `Clips`：该实体拥有的所有动画。
- `DefaultClipName`：默认播放动画。
- `PlayOnStart`：场景运行时是否自动播放默认动画。
- `FireEvents`：是否允许动画事件在运行时触发命令。
- `CurrentClipName / ElapsedTime / CurrentFrameIndex`：运行时播放状态。

编辑器 Inspector 里保留最常用开关；复杂编辑放到 `Animation Editor` 专门窗口里完成。

## 3. 动画事件

动画事件是本轮升级的关键。它让动画能在某一帧附近“说话”，但动画系统本身不直接知道玩法规则。

事件字段：

- `Time`：触发时间，单位秒。
- `Name`：事件名，例如 `hit`、`footstep`、`recover`、`flash`。
- `Command`：要执行的命令。

支持占位符：

```text
{entity}  当前播放动画的实体名
{clip}    当前 Clip 名
{event}   当前事件名
```

常见写法：

```text
event:attack_hit
anim:play:{entity}:idle
anim:play:Enemy_Bear:hurt
turn:skill:player:arc_slash
```

这样设计后，动画系统只负责“在正确时间发命令”，具体是伤害结算、音效、镜头震动、切场景还是剧情推进，都交给 `CommandBus`、`.wts` 或对应玩法模块。

## 4. 动画命令

`CommandBus` 当前支持以下 `anim:` 命令：

```text
anim:play:<EntityName>:<ClipName>
anim:restart:<EntityName>
anim:pause:<EntityName>
anim:resume:<EntityName>
anim:stop:<EntityName>
anim:seek:<EntityName>:<Time>
```

示例：

```text
anim:play:Hero:attack_1
anim:seek:VN_HeroPortrait:0.35
anim:pause:Boss
```

注意：当前命令目标仍使用实体名。后续稳定 Entity 引用系统继续深入后，可以把命令目标升级为 UUID 或编辑器对象选择器，减少改名带来的风险。

## 5. 编辑器工作流

### 5.1 创建动画

1. 选中带 `SpriteRendererComponent` 的实体。
2. 添加 `SpriteAnimatorComponent`。
3. 打开 `Animation Editor`。
4. 点击 `+ Add Clip` 创建动作。
5. 设置 `Loop`、`Set Default`、`Play On Start` 和 `Fire Events`。

### 5.2 使用 spritesheet

推荐使用 `Sprite Sheet Picker`：

1. 选中带 `SpriteAnimatorComponent` 的实体。
2. 打开 `View / Sprite Sheet Picker`，或在 `Animation Editor / Spritesheet / Atlas Generator` 点击 `Open Sprite Sheet Picker`。
3. 从 `Content Browser` 把图集拖到图集选择器顶部。
4. 填写 `Columns / Rows`，在预览区点击起始格。
5. 横向连续帧选择 `Horizontal Strip`，设置 `Frame Count / Frame Step / Duration`。
6. 点击 `Replace Clip With Sequence` 或 `Append Sequence To Clip`。

`Animation Editor` 里仍保留旧的 `Spritesheet / Atlas Generator` 快速入口，适合熟悉参数后快速生成；需要视觉选格、UI 图标 atlas 或横向帧条切割时，优先用 `Sprite Sheet Picker`。

生成后 Clip 中的每一帧会引用同一张贴图，只改变 UV。正式角色和特效资源都建议走这条路径。

### 5.2.1 静态 Sprite 和 UI 图标

图集不只服务动画。`SpriteRendererComponent` 和 `UIImageComponent` 都支持 `UVMin / UVMax`：

- 静态角色部件、道具、掉落物可以从同一张 atlas 里选子图。
- UI 技能图标、背包物品、结算掉落图标可以放在一张 `ui_icons_*.png` 里。
- Inspector 的 `Open Sprite Sheet Picker` 会把选中格直接写回目标组件并参与场景序列化。

### 5.3 添加动画事件

1. 在时间轴移动到需要触发的时间。
2. 点击 `+ Add Event` 或在 Events 轨道上双击。
3. 在 `Events` 表格里填写事件名和命令。
4. 运行时由 `AnimationSystem` 自动触发。

事件可以用来做：

- 攻击命中帧。
- 脚步声。
- UI 面板打开完成后允许点击。
- VN 表情差分切换。
- 回合制技能演出中间的伤害结算。
- 横板战斗技能特效、hit pause、屏幕震动和连招窗口。

## 6. 与三种玩法的关系

### VN

VN 不应该把表情切换和 UI 动画全写死在 VN 系统里。当前运行时已经支持“表情同名 Clip 优先”：如果 `VN_Character_<name>` 立绘实体有名为 `happy`、`serious` 等表情名的 `AnimationClip`，VN 系统会优先播放该 Clip；如果没有同名 Clip，则回退到原来的静态 PNG 差分。

后续人物立绘、表情闪动、对话框淡入、BGM 提示条都可以使用动画 Clip。VN 脚本只发命令，例如：

```text
anim:play:VN_HeroPortrait:surprised
```

### 横板战斗

横板战斗需要最依赖动画事件：

- 起手帧、命中帧、收招帧。
- 空中普攻命中时的滞空和击飞。
- 上挑、断限追击、受击、倒地、起身。
- 音效、特效和镜头反馈。

当前 SideCombat 已经把 `side_combat_tuning.yaml` 里的单帧序列自动桥接为 `SpriteAnimatorComponent + AnimationClip`：模块仍负责输入、物理、hitbox 和数值，动画系统负责帧采样和写回贴图。后续替换成 spritesheet 时，只需要用 Sprite Sheet Picker 或导入脚本生成同名 Clip，玩法状态选择逻辑不需要重写。

### 回合制战斗

回合制技能适合做成“演出 Clip + 事件脚本”：

```text
anim:play:Hero:turn_arc_slash
```

动画事件到达 `hit` 时触发：

```text
turn:skill:resolve_hit
```

当前 TurnCombat 也会把 `IdleFramePattern / AttackFramePattern / HitFramePattern / DownFramePattern` 自动桥接为通用 Clip。这样等待动画、结算伤害、播放受击、掉落结算都能排成清晰流程。

## 7. 后续升级路线

1. 把现有 Sandbox DEMO 的关键演出逐步迁到 AnimationClip 和动画事件。
2. 为动画事件增加对象选择器，减少手写实体名。
3. 增加资源级 `.wtanim` 文件，让同一套动画能在多个 prefab / scene 之间复用。
4. 增加 Animation State Machine，用状态和转移规则管理 `idle -> run -> attack -> recover`。
5. 增加 Sprite Atlas 资源导入器，自动识别格子、命名帧、批量生成 Clip，并把图集定义保存为可复用资源。
6. 增加事件预览：编辑器拖动时间轴时可选择是否模拟事件，但默认不触发会改变场景状态的命令。

当前阶段先把“Clip + spritesheet + 属性轨道 + 事件轨道 + CommandBus”打稳。Sandbox DEMO 迁移放到下一轮单独讨论，这样不会在底层还变动时把现有内容一次性搬乱。
