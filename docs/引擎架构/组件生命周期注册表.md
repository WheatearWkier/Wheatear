# 组件生命周期注册表

本文记录 Wheatear 当前的组件生命周期机制。它用于替代早期写在 `Scene` 里的 `OnComponentAdded<T>` 模板钩子，把“组件创建、更新、移除后要做什么”交给各系统自己注册。

## 目标

- `Scene` 只负责实体和注册表，不再知道每一种组件的初始化细节。
- 模块可以注册自己的组件生命周期逻辑，例如相机初始化、UI 缓存刷新、动画资源预热、脚本启动状态重置。
- 不只 `Entity::AddComponent` 能触发初始化，直接走 `entt::registry.emplace / patch / remove / destroy` 的代码路径也能触发。
- 避免继续在 `Scene.cpp` 里堆模板特化，降低大翻译单元和 `/bigobj` 风险。

## 运行结构

核心类是：

```cpp
Wheatear::ComponentLifecycleRegistry
```

场景创建时会调用：

```cpp
RegisterCoreComponentLifecycles();
ComponentLifecycleRegistry::BindScene(*this);
```

场景销毁时调用：

```cpp
ComponentLifecycleRegistry::UnbindScene(*this);
```

注册表内部接入 EnTT 的三个 signal：

- `on_construct<Component>`：组件创建。
- `on_update<Component>`：组件被 `patch / replace / emplace_or_replace` 更新。
- `on_destroy<Component>`：组件移除或实体销毁时触发。

当前核心注册项：

- `CameraComponent` 创建或更新后，如果 Scene 已有 viewport size，就同步设置 SceneCamera 的 viewport。

## 推荐注册方式

系统或模块启动代码里注册生命周期回调：

```cpp
ComponentLifecycleRegistry::RegisterOnAdded<MyComponent>(
    "MySystem.MyComponent.Initialize",
    [](Scene& scene, Entity entity, MyComponent& component)
    {
        // Initialize component-owned runtime data here.
    });
```

更新回调：

```cpp
ComponentLifecycleRegistry::RegisterOnUpdated<MyComponent>(
    "MySystem.MyComponent.Refresh",
    [](Scene& scene, Entity entity, MyComponent& component)
    {
        // Rebuild derived state after inspector edits or registry.patch.
    });
```

移除回调：

```cpp
ComponentLifecycleRegistry::RegisterOnRemoved<MyComponent>(
    "MySystem.MyComponent.Cleanup",
    [](Scene& scene, Entity entity, MyComponent& component)
    {
        // Release references owned by this component.
    });
```

回调名称必须稳定且唯一。重复注册同名回调会替换旧回调，用于避免多个 Scene 创建时重复堆叠同一份逻辑。

## 和系统生命周期的边界

组件生命周期负责“小而明确的组件钩子”：

- 创建时补默认运行时状态。
- Inspector 修改后刷新派生数据。
- 移除时释放组件自己的临时引用。

`ISystem` 仍负责“每帧和场景运行状态”：

- `OnRuntimeStart / OnRuntimeStop`
- `OnUpdateRuntime`
- `OnEditorStart / OnEditorStop`
- `OnUpdateEditor`
- `OnEntityCreated / OnEntityDestroy`

也就是说，不要把大段 gameplay 流程写进组件生命周期回调。比如战斗 AI、VN 剧情推进、回合推进仍应放在系统或事件脚本里。

## 工程规范

- 回调应短小，避免创建复杂依赖链。
- 不在回调里保存裸 `Entity` 长期引用；需要持久引用时保存 `UUID`。
- `OnRemoved` 回调中只依赖当前组件自身和非常稳定的 Scene 服务，因为实体销毁时其它组件的销毁顺序不应作为 gameplay 规则。
- 模块组件的注册入口应靠近模块 bootstrap，而不是写回 `Scene.cpp`。
- 如果回调需要加载资源，应优先登记请求或刷新轻量状态，避免创建组件时造成明显卡顿。

## 迁移状态

本轮已完成：

- 新增 `ComponentLifecycleRegistry.h/cpp`。
- `Scene` 构造/析构接入 Bind/Unbind。
- 删除 `Scene::OnComponentAdded<T>` 旧模板钩子。
- `Entity::AddComponent / AddOrReplaceComponent` 不再手动调用 Scene 钩子。
- `CameraComponent` viewport 初始化迁移到注册表。
- 源码中的旧中文/乱码 `//` 注释已批量清理，后续新增注释优先使用简洁英文。

后续适合迁移的组件：

- `UICanvasComponent / UIWidgetComponent`：创建或更新时刷新 UI 父子缓存。
- `SpriteAnimatorComponent`：更新 Clip 或 sheet 参数时刷新采样缓存。
- `EventScriptComponent`：脚本路径变化时清理已解析缓存。
- 玩法模块 Level 组件：调参文件路径变化时触发重新加载或标记 dirty。
