# 七点打磨记录 2026-08-02

本轮目标是把玩法架构、编辑器工具和竖切流程继续向“可长期维护的类型化 2D 游戏引擎”推进。原则是：能统一的能力收进服务层，玩法系统只保留循环和状态机；能由数据和事件驱动的流程，不继续散落在场景字段里；编辑器工具要从“能看”升级到“能改、能校验、能预览”。

## 1. Progression 设置职责拆分

- `GameProgress::State` 不再保存 `Settings`，设置状态统一由 `UserSettings` 管理。
- VN 和据点设置命令直接读写 `UserSettings`，避免存档进度和用户偏好出现两份状态。
- 新增 `ProgressionSettingsCommandService`，负责设置命令识别、执行、保存、运行时应用和设置页状态文本。
- `GameProgress` 保留 `progression:` 命令入口，但设置命令的具体逻辑已从进度主文件剥离。

## 2. VN 运行时输入服务

- 新增 `VisualNovelInputService`。
- VN System 不再直接读取鼠标、数字键和输入绑定，而是消费一帧 `InputSnapshot`。
- 这样后续接手柄、改键面板、输入录制/回放或编辑器预览输入时，只需要扩展输入服务。

## 3. 运行时实体引用优化

- 新增 `SideCombatEntityReferenceService`。
- 横板战斗玩家和 Boss 的高频引用改为“首次用作者名解析，运行时缓存 UUID，之后优先按 UUID 查找”。
- `SideCombatSystem` 和 `SideCombatComboService` 不再直接按名字查玩家/Boss。
- 现有 UI 控件名称绑定仍保留为作者层入口，后续逐页迁移为 Inspector 可选实体引用。

## 4. WAO Action Editor 二阶段

- 顶部新增 `Reload YAML`，可热加载 `assets/gameplay/actions` 下的 action YAML。
- Recipe 编辑模式新增 `Effects` 编辑区，支持新增、删除、选择并修改单条效果。
- 单条效果支持编辑类型、属性 ID、状态 ID、信号 ID、数值、回合数、秒数和持续策略。
- 保存 YAML 时会写回 `effects`，不再只保存基础字段。
- 新增 `Validation` 页，检查 ID、时间线、资源路径、资源消耗和效果字段。
- 新增 `Preview` 页，用时间轴展示前摇、命中帧、后摇、取消窗口和资源/信号概要。

## 5. 编辑器大面板拆分

- `AnimationEditorPanel.cpp` 拆出 `AnimationEditorPanelSections.cpp`，承载 spritesheet/atlas、events、frames 三块编辑区。
- `EditorLayerBaseUI.cpp` 拆出 `EditorLayerDockspace.cpp`，默认 Dock 布局构建不再混在主 UI 渲染文件中。
- 后续建议继续把 Canvas overlay 拆为专门编辑工具，但本轮先拆低风险且稳定的大块。

## 6. 战棋流程脚本化

- `VerticalSliceTacticalCombat.wt` 的胜利/失败跳转改为 `event:tactical_combat_victory` 和 `event:tactical_combat_retry`。
- `vertical_slice_flow.wts` 新增战棋胜利事件：设置 `FLAG_CH01_TACTICAL_COMBAT_CLEARED`、保存一号槽、等待后回据点。
- 失败事件统一回到战棋场景重试。
- 以后战棋结算、奖励、剧情 flag 和章节分支都应继续写在 `.wts`，不要散落在场景字段中。

## 7. 当前架构结论

Wheatear 当前更适合继续坚持这套分层：

- `System`：玩法循环、状态机、每帧调度。
- `Service`：具体能力，如输入、目标、行动、命中、奖励、UI、反馈、设置、引用解析。
- `WAO`：动作语义、效果账本、表现信号、调试和轻量 authoring。
- `.wts`：低频流程编排、保存/读取、条件分支、场景跳转。
- `YAML / VN 数据`：高频可调内容、台词、战斗参数、动作配方。

这套结构不是照搬 UE GAS 或 Unity，而是把它们“数据驱动、能力拆分、调试可见”的思想吸收后，变成更适合 Wheatear 当前体量和 2D 类型化玩法目标的工程方案。
