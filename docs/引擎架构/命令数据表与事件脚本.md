# 命令、数据表与事件脚本设计

更新时间：2026-07-29

本文记录 Wheatear 当前推荐的运行时内容驱动方式：`CommandBus + 数据表 + .wts 事件脚本`。目标是先不用 C#，也不急着引入 Lua，而是把引擎自己的轻量流程能力做正式，让策划能在编辑器里把常见游戏逻辑配置出来。

## 总体分工

- `CommandBus`：统一执行短命令，例如切场景、打开 UI 分页、修改成长进度、触发事件。
- 数据表：保存长期、可调、可批量维护的数据，例如 `side_combat_tuning.yaml`、VN `.vn` 剧本、技能树、装备、掉落和关卡配置。
- `.wts` 事件脚本：把若干命令按顺序组织起来，支持等待和简单条件，适合做门、按钮、剧情节点、战斗结算后的流程分发。

这三者的关系是：

```text
UI 按钮 / VN 选择 / 战斗结算 / 触发器
        ↓
CommandBus
        ↓
progression: 修改存档状态
ui: 修改通用 UI 控件
event: 启动 .wts 事件
scene: 进入 SceneTransitionService
        ↓
宿主层执行实际加载
```

## 命令系统

命令是短字符串，适合挂在 UI 按钮、滑条、VN 选择项、战斗结算命令和事件脚本里。

当前原生命令包括：

- `scene:assets/scenes/VerticalSliceHub.wt`：请求切换场景。
- `newgame:assets/scenes/VerticalSliceIntro.wt`：重置成长进度后进入指定场景。
- `loadgame:assets/scenes/VerticalSliceIntro.wt:1`：读取 1 号槽后进入指定场景。
- `quit`：退出游戏。
- `progression:save_1`：保存竖切进度。
- `progression:load_1`：读取竖切进度。
- `progression:set_flag:FLAG_CH02_TUTORIAL_STARTED`：设置剧情旗标。
- `progression:clear_flag:FLAG_CH02_TUTORIAL_STARTED`：清除剧情旗标。
- `progression:set_chapter:3`：切换当前章节编号，用于章节解锁和后续剧情分发。
- `progression:select_skill_node:magic_sword_core`：选中技能树节点。
- `progression:learn_selected_skill_v2`：学习当前选中的技能节点。
- `ui:pager:Equipment_Pager:next`：切到某个 Pager 的下一页。
- `ui:pager:Equipment_Pager:page:2`：切到某个 Pager 的指定页。
- `event:open_skill_tree`：触发当前场景中所有事件脚本组件的 `open_skill_tree` 事件。
- `event:FlowController:open_skill_tree`：只触发 Tag 为 `FlowController` 的实体上的对应事件。

## SceneTransitionService

场景切换能力属于引擎运行时，不属于 `WheatearSandbox` 的业务逻辑。

当前实现中：

- `.wts`、UI 按钮、VN 选择等只发出 `scene:` / `newgame:` / `loadgame:` 命令。
- `CommandBus` 把这些命令转成 `SceneTransitionService` 的结构化请求。
- `RuntimeSceneLayer` 只作为宿主消费请求，执行实际卸载旧场景、加载新场景、启动系统。

这样做的好处是事件脚本不需要知道 Sandbox，也不需要直接调用加载函数。后续编辑器 Play Mode、正式 Player、测试宿主都可以消费同一套场景切换请求。

## 数据表

数据表用于描述“大量可调内容”，不适合写进 `.wts`。

推荐边界：

- 战斗手感、hitbox、技能输入、章节解锁：写在 `assets/vertical_slice/data/side_combat_tuning.yaml`。
- VN 台词、人物、表情、BGM、选择项：写在 `.vn` 剧本里，并通过 VN 编辑器维护。
- 装备、掉落、技能树、好感、存档状态：当前由 `GameProgress` 提供竖切实现，后续应拆成独立服务和数据资产。
- 单次流程编排，例如等待 0.3 秒后切场景、按条件打开技能树：写在 `.wts`。

原则是：数据表负责“是什么”，事件脚本负责“什么时候做什么”，命令负责“执行一个明确动作”。

## .wts 事件脚本

`.wts` 是 Wheatear 自己的轻量事件脚本格式。它不是通用编程语言，而是一个可被编辑器和运行时稳定理解的流程脚本。

示例：

```text
event on_start:
    wait 0.15
    progression:select_skill_node:magic_sword_core
end

event open_skill_tree:
    scene:assets/scenes/VerticalSliceSkillTree.wt
end

event save_slot_1:
    progression:save_1
end
```

当前语法：

- `event <name>:`：定义事件块。
- `end`：结束当前事件块。
- `wait 0.25`：等待指定秒数。
- `command <cmd>` 或直接写命令：执行一条 `CommandBus` 命令。
- `if <condition>` / `endif`：简单条件分支。
- `#` 或 `//` 开头：注释。

当前条件：

- `always` / `never`
- `flag <name>`
- `not flag <name>`
- `skill <skillId>`
- `dungeon <dungeonId>`
- `completed <dungeonId>`
- `last_dungeon <dungeonId>`
- `equipment <equipmentId>`
- `equipped <equipmentId>`
- `chapter >= 3`
- `material beast_core >= 2`

## 编辑器使用流程

1. 在 `Content Browser` 中创建或选择一个 `.wts` 文件，例如 `assets/events/vertical_slice_flow_sample.wts`。
2. 在场景中创建一个空实体，建议命名为 `FlowController` 或具体玩法名。
3. 在右侧 `Properties` 点击 `Add Component / Scripting & Audio / Event Script`。
4. `Script Path` 填 `.wts` 路径，例如 `assets/events/vertical_slice_flow_sample.wts`。
5. `Start Event` 填 `on_start`。
6. 如果需要进场自动执行，勾选 `Run On Start`；如果只想由按钮触发，就取消勾选。
7. 如果同一个事件只允许执行一次，勾选 `Run Once`。
8. 需要按钮触发时，在按钮 `On Click` 填 `event:FlowController:open_skill_tree`。

组件下方会显示 `.wts` 文本编辑器，可以直接改脚本内容并保存。

## 竖切 Demo 迁移规范

当前竖切 demo 的主流程已经迁移到统一的 `FlowController + .wts` 模式：

- 公共流程脚本：`assets/events/vertical_slice_flow.wts`。
- 每个竖切场景都有一个名为 `FlowController` 的实体，并挂载 `EventScriptComponent`。
- UI 按钮不再直接写 `scene:`、`newgame:`、`loadgame:` 或 `quit`，而是写 `event:FlowController:<eventName>`。
- VN 选择项也支持 `event:` 入口，例如 `event:FlowController:go_fake_combat`。
- 战斗胜利 / 失败命令也走 `event:`，例如 `event:FlowController:side_combat_victory`。
- `.wts` 内部再按顺序执行 `progression:`、`wait`、`scene:`、`newgame:`、`loadgame:` 等具体动作。

目前已迁移的核心入口包括：

| 触发位置 | 事件 |
| --- | --- |
| 主菜单新游戏 / 继续 / 退出 | `menu_new_game`、`menu_load_game`、`menu_quit` |
| VN 序章进入假玩法 / 正式战斗 | `go_fake_combat`、`go_side_combat` |
| 假玩法胜利后进入转折 VN | `fake_combat_victory` |
| 正式战斗胜利 / 重试 | `side_combat_victory`、`side_combat_retry` |
| 黑林兽道胜利 / 重试 | `beast_path_victory`、`beast_path_retry` |
| 结算页回据点 / 重试上一关 | `result_go_hub`、`result_retry_last_dungeon` |
| 据点页面跳转 | `go_dungeon_select`、`go_skill_tree`、`go_equipment`、`go_relationship`、`go_support`、`go_save_load`、`go_settings`、`go_next_story` |
| 存档读取 | `save_slot_1`、`load_slot_1`、`save_slot_1_then_hub`、`load_slot_1_then_intro` |

后续新增竖切页面时，优先照这个模式做：页面上的按钮只触发 `event:`，具体的保存、读档、等待、条件判断和切场景全部集中写进 `.wts`。这样策划可以在编辑器里看懂流程，程序也能保持运行时职责清晰。

当前已经接实的流程：

- 假玩法胜利：设置 `FLAG_CH01_FAKE_COMBAT_CLEARED`，保存一号槽，再进入假玩法后的 VN。
- 正式 SideCombat 胜利：设置 `FLAG_CH02_TUTORIAL_CLEARED`，保存一号槽，再进入结算页。
- 黑林兽道胜利：保存一号槽，再进入结算页。
- 结算页回据点：保存一号槽，再进入据点。
- 结算页重试：根据 `last_dungeon` 回到主线战斗或黑林兽道。
- 据点继续剧情：检查 `FLAG_CH02_BOSS_DEFEATED`，设置 `FLAG_CH03_PREVIEW_STARTED`，章节切到第 3 章，保存后进入第三章预告。

仍然只是骨架的方向：

- 具体教程提示文本还没有迁成 `tutorial:` 命令或教程数据表。
- 后续章节的复杂条件分发暂时只保留 `flag/chapter/completed/last_dungeon` 这些能力，等第三章之后内容变多再继续扩展。

## 适合用 .wts 的地方

- 按钮点击后先保存，再等待一小段时间，最后切场景。
- 战斗胜利后根据章节、材料、技能状态进入不同结算或剧情。
- 剧情里某个选择触发成长状态变化，然后跳转到据点。
- 教程关卡中依次显示提示、解锁按钮、打开下一场景。

## 暂不适合用 .wts 的地方

- 每帧移动、敌人 AI、战斗动作状态机、碰撞求解。
- 大量数值计算，例如伤害公式、掉落权重、技能冷却。
- 复杂 UI 排版和动画曲线。
- 需要高性能或高频调用的底层逻辑。

这些内容仍应放在 C++ 系统、数据表或专门模块里。

## 和 C# / Lua 的关系

当前阶段推荐先不用 C#，也不急着引入 Lua。Wheatear 先把自己的命令、数据表和事件脚本体系做扎实：

- 日常关卡流程和 UI 跳转用 `.wts`。
- 大量可调内容用 YAML / VN 数据。
- 高频复杂逻辑用 C++ 模块。
- 后续如果确实需要玩家或设计师写复杂逻辑，再把 Lua、Wren、AngelScript 或重新整理后的 C# 作为可选脚本层接进来。
- C# / Mono 现在是构建期可选能力，默认构建不链接 Mono。需要时使用 premake `--csharp-scripting` 重新生成项目，并在运行/打包时启用脚本。

这样面试时也能说清楚：Wheatear 不是简单照搬 Unity，而是先建立了适合自己引擎的内容驱动管线，再按需要开放更强的脚本能力。

## 编辑器可视化事件流程图

WheatearEditor 新增 `Event Script Graph` 窗口，用来把 `.wts` 的事件流程画成节点图。入口有两个：

- `View / Event Script Graph`：打开默认竖切流程脚本，或打开当前选中实体上的 `EventScriptComponent`。
- `EventScriptComponent` Inspector 中的 `Open Event Graph`：直接打开当前组件的 `Script Path` 和 `Start Event`。

第一版流程图是安全查看器，不直接写回 `.wts`：

- `event` 会显示为开始节点。
- `progression:`、`scene:`、`event:`、`ui:` 等命令显示为命令节点。
- `wait` 显示为等待节点。
- `if/endif` 会用侧边曲线标出条件作用范围。
- 点击节点可以在右侧看到源行、类型和命令内容。

暂时不做直接拖线改写脚本，是因为 `.wts` 文本目前更适合版本管理、复制、搜索和手工排错。等事件数量继续增长，再把节点编辑、命令参数面板、条件分支编辑和保存回脚本作为第二阶段。
