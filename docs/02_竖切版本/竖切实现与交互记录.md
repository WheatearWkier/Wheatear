## 《Wheatear 异世界项目》竖切实现清单 v0.5

### 0. 文档定位

本文档负责把当前企划拆成第一个可玩竖切版本的工程计划、内容范围、数据资产、里程碑和验收标准。

竖切版本目标不是做完整游戏，而是证明以下闭环真实可用：

`主菜单 -> VN 剧情 -> 第一章假玩法 -> 第二章正式横板战斗 -> Boss -> 掉落结算 -> 据点 UI -> 装备 / 技能强化 -> 重刷副本 -> 继续剧情 -> 打包运行`

只要这条链路跑通，后续扩章节、角色、美术和 Boss 就有稳定底座。

### 1. 竖切范围

#### 1.1 必须包含

| 模块 | 内容 |
| --- | --- |
| 主菜单 | 新游戏、继续、退出 |
| VN | 序章、第一章前后剧情、第二章剧情、第三章入口 |
| 假玩法 | 第一章当前 ArcadeCombat 模块，作为剧情误导 |
| 正式横板 | 第二章 SideCombat 竖切 |
| 主角 | 移动、一段跳、闪避、普攻、上挑、基础跳斩、火球 |
| Boss | 黑熊丈夫三阶段 |
| 敌人 | 小型近战、小型远程、黑熊母熊演出、黑熊丈夫 |
| 掉落 | 材料、少量装备、首通奖励、评分奖励 |
| 背包 | 材料计数、装备实例 |
| 魔剑 | Lv1-Lv3，基础技能树 6-8 个节点 |
| 装备 | 防具、饰品 1、强化 +0 到 +3 |
| 据点 UI | 首页、继续剧情、副本选择、战斗结算、魔剑技能树、装备强化、好感关系、支援配置、保存读取、系统设置 |
| 支援 | 导师提示 / 临时支援，主动支援选择和锁定状态 |
| 存档 | 章节、材料、装备、技能、副本完成标记、好感关系、支援选择、设置状态 |
| 打包 | 只打包引用资源到 `.wtpack` |

#### 1.2 暂不包含

- 完整后宫路线。
- 第三章及以后完整战斗内容。
- 完整随机词条。
- 装备重铸。
- 全 60 个魔剑技能。
- 全部圣兽试炼。
- 七大罪战场。
- 国师最终战。
- 可探索据点。
- 复杂 AI 行为树编辑器。

### 2. 推荐工程边界

#### 2.1 引擎核心

引擎核心只提供通用能力：

- 场景。
- 实体和组件。
- 渲染。
- 输入。
- 音频。
- 资源。
- 序列化。
- UI。
- 打包。

不把具体游戏规则塞进核心 `Systems`。

#### 2.2 游戏模块

建议保持如下模块边界：

| 模块 | 职责 |
| --- | --- |
| `VisualNovel` | VN 对话、选项、场景跳转 |
| `ArcadeCombat` | 第一章假玩法 |
| `SideCombat` | 正式横板战斗 |
| `Progression` | 等级、经验、魔剑、技能树 |
| `Inventory` | 材料、装备、掉落 |
| `Relationship` | 好感、支援、角色事件 |
| `Hub` | 据点 UI 和流程 |

如果代码层现在还没有这些模块，竖切阶段可以先用较薄的数据结构和服务类实现，但命名和职责要按这个方向走。

#### 2.3 建议目录

```text
Wheatear/src/Wheatear/Modules/SideCombat/
Wheatear/src/Wheatear/Modules/Progression/
Wheatear/src/Wheatear/Modules/Inventory/
Wheatear/src/Wheatear/Modules/Relationship/
WheatearEditor/src/Modules/Hub/
WheatearEditor/src/Modules/Dungeon/
WheatearEditor/src/Modules/Inventory/
```

注意：

- `Systems` 目录只放游戏引擎必须的基础系统。
- VN、假玩法、正式横板、装备、好感、据点都属于可选游戏模块或编辑器工具模块。

### 5. 里程碑

#### M0：数据骨架

目标：

- 确定数据结构。
- 能加载基础 JSON / YAML / 内置表。
- 能保存最小存档。

验收：

- 能读取一个副本定义。
- 能读取一个敌人定义。
- 能读取一个掉落表。
- 能保存章节标记、材料数量、已解锁技能。

#### M1：VN 与场景跳转

目标：

- 主菜单进入序章。
- VN 对话、选项和场景跳转稳定。
- 第一章假玩法可从 VN 进入，再返回 VN。

验收：

- 新游戏能完整走到第一章假玩法。
- 假玩法结束后能写入剧情标记。
- 能跳到第二章魔剑觉醒 VN。

#### M2：SideCombat 最小战斗

目标：

- 建立正式横板战斗最小模块。
- 主角能移动、一段跳、闪避、普攻。
- 敌人能受击、死亡、掉落。

验收：

- 主角不会穿地或卡死。
- 小怪可被普攻击杀。
- 上挑能造成浮空。
- 跳跃后按 `J` 能打出基础跳斩，并能接在上挑后维持浮空。
- 火球能补 hit 或打断远程。

#### M3：教程副本和黑熊 Boss

目标：

- 完成 `CH02_MAIN_BearAwakening`。
- 做出黑熊丈夫三阶段 Boss。
- 做出独立战斗结算页面。

验收：

- 玩家能按教程完成移动、跳跃、闪避、上挑、跳斩、火球。
- 黑熊丈夫有 P1/P2/P3 行为变化。
- 普通玩家用短空连和读招能打赢。
- Boss 死亡后掉落材料并触发结算。

#### M4：掉落、背包、装备

目标：

- 材料进入背包。
- 装备进入背包。
- 装备可穿戴。
- 装备可强化到 +3。

验收：

- 打完 Boss 能获得初级魔核和装备。
- 据点能显示材料数量。
- 穿戴装备后属性变化。
- 强化装备消耗材料并提升属性。

#### M5：魔剑技能树页面

目标：

- 做出 6-8 个基础技能节点。
- 技能可通过材料解锁。
- 技能解锁后能在战斗中使用或生效。

验收：

- 玩家可用材料把魔剑升到 Lv2 或 Lv3。
- 缺材料时显示缺什么和去哪刷。
- 解锁技能后快捷栏或战斗行为更新。

#### M6：据点 UI 闭环

目标：

- 战斗结算后回据点。
- 据点能继续剧情、进副本、强化装备、解锁技能、查看好感、配置支援、保存读取和调整基础设置。

验收：

- 打完第二章主线后回据点。
- 可从据点进入黑林兽道。
- 黑林兽道结算后回据点。
- 可打开好感关系页并看到当前队友状态。
- 可打开支援配置页并切换可用主动支援。
- 可保存和读取一号竖切进度。
- 可调整文本速度，并在 VN 中体现。
- 可从据点继续到第三章入口。

#### M7：打包与运行

目标：

- 编辑器能把竖切项目打包。
- 打包只包含引用资源。
- `content.wtpack` 可被运行时加载。

验收：

- 打包目录不复制整个 `assets`。
- 包内包含 VN、场景、贴图、占位音频、数据表、字体、UI 图标等引用资源。
- 打包后的 `WheatearSandbox` 能从主菜单跑完整竖切。
- 无脚本路径、资源路径、中文路径崩溃。

### 6. 系统依赖顺序

推荐先后顺序：

```text
Data / Save
-> VN Scene Flow
-> SideCombat Player Controller
-> Enemy / Hit / Damage
-> Dungeon / Room Flow
-> Loot / Inventory
-> Hub UI
-> Skill Unlock
-> Equipment Enhance
-> Package Smoke Test
```

原因：

- 没有数据和存档，后面所有系统都无法串起来。
- 没有战斗最小闭环，装备和技能没有验证场景。
- 没有掉落和据点，副本重刷没有意义。
- 没有打包验证，就不能证明编辑器能产出游戏。

### 7. 验收用玩家流程

最终竖切验收时，按这个玩家流程测试：

1. 启动打包后的游戏。
2. 进入主菜单。
3. 点击新游戏。
4. 看完序章上学路。
5. 进入异世界第一章假玩法。
6. 假玩法结束后主角吐槽。
7. 假青梅被大魔法师掳走。
8. 进入第二章，导师送魔剑。
9. 按教程学习正式横板战斗。
10. 击败黑熊母熊。
11. 魔剑吸收材料。
12. 黑熊丈夫登场。
13. 击败黑熊丈夫。
14. 进入结算页面。
15. 获得材料和装备。
16. 回到据点 UI。
17. 解锁或升级一个魔剑技能。
18. 穿戴或强化一件装备。
19. 打开副本选择并进入黑林兽道重刷。
20. 结算后回据点。
21. 打开好感关系页查看队友状态。
22. 打开支援配置页选择导师支援。
23. 在据点保存读取页或 VN 存读档覆盖层保存一次进度。
24. 打开设置页调整文本速度。
25. 点击继续剧情进入第三章入口。

只要这 25 步全部稳定，竖切就合格。

### 9. 风险和预案

| 风险 | 表现 | 预案 |
| --- | --- | --- |
| SideCombat 范围膨胀 | 一直想做更多技能和敌人 | 竖切只做 8 个技能和 1 个 Boss |
| 据点 UI 太复杂 | 页面多但流程跑不通 | 首页、结算、副本、装备、技能树优先 |
| 掉落系统太随机 | 玩家刷不到关键材料 | 首通关键材料必给，重刷做追求 |
| 好感系统过早展开 | 竖切内容被角色线拖慢 | 第三章前只预留入口 |

### 3. 当前战斗输入

| 输入 | 行为 | 设计目的 |
| --- | --- | --- |
| `A / D` 或左右方向键 | 左右推进 | 横向推进和追击 |
| `W / S` 或上下方向键 | 纵深走位 | 接近《机甲旋风》式横向清场视角 |
| `K` / `Space` | 一段跳 | 躲避远程攻击，也可接空中连击；正式文案以 `K` 为准，`Space` 仅保留测试兼容 |
| `J` 或鼠标左键 | 地面普攻三段；空中跳斩 | 每段都能续连，跳斩负责基础空中续连 |
| `S + J` | 地面裂空上挑；空中追斩 | 主要浮空起手，空中用于续住快下落的目标 |
| `U` | 魔法弹 | 远程续连和补刀 |
| `I` | 真青梅支援 | 较长冷却的浮空续连 |
| `L` | 竖切断限追击调试键 | 当前默认隐藏 UI 提示，只用于测试后期断限底层能力 |
| `Esc / P` | 暂停切换 | 调试和试玩用 |

竖切暂不开放普通二段跳。未来“断限追击”会作为高手机制重置空中行动，而不是常驻二段跳。

战斗 HUD 只显示 `S+J / U / I / L`。`J` 普攻和 `K` 跳跃是基础动作，不进入技能栏；后续 UI 空间紧张时优先使用图标和悬浮 tooltip，不把长说明塞进技能槽。

#### 3.1 当前战斗视角实现

v0.2 已从“平台式 X/Y 重力”改成“横向推进 + 纵深战斗带 + 独立空中高度”：

- `RuntimeGroundPosition.x` 表示左右推进。
- `RuntimeGroundPosition.y` 表示地面纵深站位。
- `RuntimeAirHeight` 表示浮空高度，不再把角色当作平台游戏那样直接改地面 Y。
- 攻击判定同时检查 X 距离、纵深距离和空中高度区间。
- 角色脚下阴影会根据浮空高度淡出，帮助玩家看清 Boss 是否真的被挑起来。

这套结构是后续“浮空连击、断限追击、Boss 保护槽”的基础。普通玩家可以地面立回通关，高手玩家可以研究如何把 Boss 留在空中。

正式横板战斗调参表：

```text
WheatearEditor/assets/sandbox/data/side_combat_tuning.yaml
```

战斗调参优先使用 WheatearEditor 的 `Side Combat Tuning Editor`，不要直接改 C++。必要时仍可手动编辑 `side_combat_tuning.yaml`，因为 YAML 仍是运行时唯一数据源：

- `player`：玩家移速、一段跳高度、重力、空中控制、普攻 / 上挑 / 魔法 / 支援 CD、连招窗口。
- `combat`：连击保留时间、受击无敌、防御减伤公式、最小伤害。
- `airCombo`：空中动作次数、跳斩 CD、空中追斩 CD、断限冷却、断限窗口、低空威胁线、高空安全线。
- `protection`：Boss 保护条上限、保护衰减、满槽脱离时间、断限压回保护条、保护 HUD 调试开关。
- `enemy`：敌人追击速度、攻击距离余量、Boss 血量阶段、冲撞和震波触发距离。
- `pickup`：掉落拾取半径、吸附半径、吸附速度。
- `movement`：纵深边界、纵深速度、排序尺度。
- `visuals`：脚下阴影透明度和浮空淡出。
- `reactions`：Boss 受击浮空修正。
- `attacks`：每个招式的判定大小、偏移、伤害、硬直、浮空力度、特效序列帧、帧率。
- `skills`：技能定义，记录技能名、输入、连招职责、关联攻击 ID、首次解锁章节和是否核心动作。
- `progression.profiles`：章节解锁配置，按 `LevelId` 决定本场战斗开放哪些技能、哪些机制可见、哪些后期能力仅供开发调试。

编辑器入口：

- 选中带 `SideCombatLevelComponent` 的实体，在 Inspector 点击 `Open Side Combat Tuning Editor`。
- 或者从顶部菜单 `View / Side Combat Tuning Editor` 打开。
- `Feel` 页签调跳跃、重力、滞空、上挑、空中普攻、空中追击和断限追击。
- `Rules` 页签调战斗规则、Boss 保护槽、敌人 AI、拾取物、纵深移动和反馈。
- `Attacks` 页签逐招式调 hitbox、伤害、前后摇、取消窗口、击飞、特效和音效。
- `Skills / Progression` 页签调技能定义、技能开放和关卡 profile。

调跳跃高度优先改：

```yaml
player:
  jumpImpulse: 7.8
  gravity: 20.0
```

`jumpImpulse` 越高，起跳越高；`gravity` 越高，下落越快。竖切仍保持常规一段跳，未来只有“断限追击”会临时刷新空中行动。

运行时读取规则：

- 编辑器或直接运行 Sandbox：战斗场景启动时读取工程内的 `side_combat_tuning.yaml`。
- 打包开发版：打包器会把调参表同时写入 `content.wtpack`，并复制一份 loose 文件到 `Builds/Windows/Player/assets/sandbox/data/side_combat_tuning.yaml`。
- 打包运行时优先读取 loose 调参表；没有 loose 文件时才读取包内资源。
- 调参缓存会检查文件修改时间。改表后重进战斗场景即可稳定生效；攻击判定类参数会在下一次生成攻击时读取到新值。
- `attacks` 下新增动作手感参数：`startup` 前摇、`lifetime` 命中框持续、`recovery` 后摇、`cancelWindowStart / cancelWindowEnd` 取消窗口、`movementScale` 出招移动倍率。

第二章竖切的机制开放边界：

- `breakLimitEnabled: false`，断限追击不作为第二章正式玩法开放。
- `breakLimitDebugKeyEnabled: false`，避免全局绕过章节配置。
- `progression.profiles.CH02_MAIN_BearAwakening.debugSkills: [break_limit]`，只在第二章竖切 profile 下保留 `L` 键方便开发测试断限底层逻辑。
- `showBreakLimitHint: false`，默认不向玩家提示断限。
- `showBossProtectionHud: false`，默认不把 Boss 保护条显示成正式 UI。
- `showCombatStateHud: false`，默认不显示 Boss 内部运行状态。
- Boss 保护条仍然在后台运行，用来防止教程 Boss 被无限浮空；第六章再显性教学保护条，第七章再正式开放断限追击。
