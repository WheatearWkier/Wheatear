# 《Wheatear 异世界项目》竖切美术资源生成提示词 v0.3

## 0. 文档定位

本文档负责第一个可玩竖切所需美术资源的生成提示词、规格、命名和打包标签。详细尺寸、cell profile、九宫格和验收标准以 `Batch*_生产包.md` 为准；本文档作为摘要版提示词，不再保留旧规格。

目标：

- 替换当前 demo 中的方块和临时素材。
- 让 VN、正式横板战斗、据点 UI 和掉落图标风格统一：VN 保持高清 Galgame；战斗角色、敌人、场景和 VFX 改为高清像素风；战斗 HUD、据点和系统 UI 使用高清二次元 UI，只带轻微像素质感。
- 优先生成能直接放入 Wheatear 项目的 2D 资源。

注意：

- 不使用任何现有商业作品角色名或特定画师名。
- 统一使用原创二次元幻想风。
- 实际游玩部分参考 DNF 类横板动作的像素密度、清晰轮廓、横板房间层次和打击阅读性，但不能复刻任何商业角色、地图、UI、图标、文字或 Logo。
- 所有图像避免文字、水印、logo。
- 除明确写着“不透明 PNG”的背景外，所有角色、sprite、VFX、UI、图标、前景层、掉落物都必须是 **RGBA PNG 真透明**，无用区域 alpha=0。禁止白底、灰底、棋盘格底、白色 matte、半透明残底和脏 alpha。
- VN、战斗 HUD、据点和系统 UI 中承载中文、数值或 tooltip 的面板，PNG 只生成框架、角饰、高光和少量边缘纹理，中心保持透明或近透明；文字底由引擎额外绘制半透明深色 fill。不要通过修改 PNG 透明通道来控制阅读底。
- 角色年龄表现使用青年，不做低龄化或擦边设计。

## 2. 资源规格

| 类型 | 建议尺寸 | 背景 | 用途 |
| --- | --- | --- | --- |
| VN 背景 | 1920x1080 | 不透明 | 对话场景 |
| 角色半身立绘 | 1024x1536 或 1200x1800 | RGBA 透明 PNG | VN 角色 |
| 角色表情差分 | 同立绘 | RGBA 透明 PNG | 普通、笑、担心、愤怒等 |
| 战斗 Sprite 源帧 | 按 Batch03 profile，512x512 起步，大动作 640/768 cell | RGBA 透明 PNG | SideCombat，先单帧后拼 strip |
| 敌人 Sprite 源帧 | 按 Batch04 profile：小怪 512x384 / 768x384 / 512x512，Boss 1024x768 / 1280x768 | RGBA 透明 PNG | 小怪、Boss，先单帧后拼 strip |
| UI 图标 | 256x256 母版 | RGBA 透明 PNG | 材料、装备、技能 |
| 横板背景层 | 3840x2160 | 不透明或 RGBA 透明分层 | 远景、中景、前景 |

动画素材生成策略：

- 角色、敌人、Boss、VFX、世界掉落物和破碎物不要让 AI 直接生成横向长 strip。
- 先生成 `source_frames/<clip>/<clip>_000.png` 这种单帧固定画布透明 PNG，每帧单独检查完整性、比例、pivot、baseline 和 alpha。
- 单帧全部通过后，再用脚本或工具拼接成最终 `*_strip.png`，供 Sprite Sheet Picker 或导入脚本使用。
- 同一个 clip 的 `cellWidth/cellHeight` 必须取该 clip 全部帧中最大的动作包围盒，再加安全边距；定好后每帧都用同一 canvas。不同 clip 可以换 profile，不使用全角色全局最大 cell。
- 上劈、挑斩、小跳攻击、跳扑和被击飞也保持同一 clip 固定 canvas；选能容纳最高跳起帧和最高武器轨迹的 profile。离地帧脚可以离开 baseline，真正玩法位移由状态机、物理速度、`rootMotion` 或事件数据控制，图片不承担碰撞尺寸。
- 动画按状态语义拆 clip：`run_loop/walk_loop` 只做可循环移动，`hit_react/knockdown_fall/dead_fall` 做一次性过渡，`down_loop/dead_pose` 做保持姿态，`recover` 做起身。不要把跑步循环做成第一帧走路、最后一帧倒下；需要“跑步中被打倒”时单独做 transition clip，并按该 transition 的最大倒地包围盒定 cell。
- 每个动画 clip 必须随图交付 metadata：`cellWidth`、`cellHeight`、`pivotX`、`pivotY`、`baselineY` 或中心 pivot、`renderOffset`、`frameOffsetMode`。AI 提示词里要写清楚 cell 分辨率和隐形 pivot 像素坐标。
- 角色、敌人和 Boss 必须随 metadata 交付 `scaleReference`：站立帧看身体高度、头部/核心尺寸、肩宽或胸宽；倒地、死亡、跳扑看身体长轴。cell 变宽只代表透明空间变大，不代表角色可以变大。
- 攻击、受击、跳扑、投掷和 Boss 动作必须随 metadata 交付 `frameContinuity` 和 `actionPower`：动作要有起手、蓄力、命中/释放峰值、跟随和恢复；装备、武器、爪子、道具和朝向必须跨帧继承。
- 标准源帧流程中同一个 clip 内每帧 canvas 和 pivot 完全一致，不需要每帧 offset；只有验收后裁切透明边并打 atlas 时，才允许每帧图片尺寸不同，并且必须提供 `sourceRect` 和 `offsetFromPivot`。
- UI 图标、按钮状态、系统节点和 VN 命令图标属于规则 atlas，可以直接生成 spritesheet/atlas，但必须固定 cell、居中一致、无透明残底。

命名建议：

```text

aoba_smile.png
mentor_slight_smile.png
bg_modern_schoolroad_morning.png
source_frames/protag_run/protag_run_003.png
protag_run_strip.png

```

## 12. 生成与筛选规则

生成后筛选标准：

- 角色脸部可读，表情明确。
- 立绘、Sprite、VFX、UI、图标必须是 RGBA PNG 真透明；无用区域 alpha=0，不能有白底、灰底、棋盘格底、白色 matte 或脏 alpha。
- 动画类素材必须先验收单帧源文件，再拼接成 strip；AI 直接生成的横向 strip 只能作为参考，不能直接作为最终交付。
- 动画类素材必须带 `sheet_params.yaml` 或同等 metadata；缺少 `pivotX/pivotY/renderOffset`、缺少 profile、或裁切帧没有 `offsetFromPivot`，不能替换正式素材。
- 角色、敌人和 Boss 必须符合 `scaleReference`：直立帧看站立身高/头部/肩宽，倒地和跳扑看身体长轴；cell 变大不能导致人物或怪物变大。
- 攻击和 Boss 动作必须符合 `frameContinuity` 和 `actionPower`：装备、武器、爪子、道具跨帧一致，动作有蓄力、发力、命中/释放峰值、跟随和恢复。
- 战斗 Sprite 轮廓清楚，缩小后还能识别动作；同一 sheet 内 cell 尺寸固定，角色身体比例、脚底 baseline、pivot 和视觉大小一致。
- 每一帧必须是独立完整图像，身体、武器、披风、腿、爪子、特效都不能断掉，不能跨进相邻 cell。
- 魔剑、大爪子、大跳跃和大挥砍动作必须按 Batch03/Batch04 的动作包围盒使用更大 cell；剑气、冲击波、拖尾、爆光优先拆到 Batch06 独立 VFX sheet。
- 倒地和死亡动作默认按 `floor_1024` 或更大的动作专用 profile 生产；不允许为了塞进较小 cell 而缩小人物、裁切魔剑或让躺姿跨帧。
- 背景留出对话框和 UI 空间。
- 图标在 64x64 下仍然能看懂。
- 战斗 HUD、据点 UI、系统 UI 必须高清清楚，只带轻微像素质感；不能做成低分辨率粗颗粒、复古农场游戏或整套糊成像素块的 UI。
- 同一角色不同表情五官一致。
- 同一敌人不同动作体型一致。
- 不出现文字、水印、logo。

不合格直接重生：

- 手指明显错误。
- 角色左右脸差异太大。
- Sprite 动作看不出攻击方向。
- 动画类素材只有一张 AI 直接生成的横向 strip，没有对应 `source_frames/<clip>/` 单帧源文件和参数记录。
- Sheet 内任意一帧人物大小明显变化、站位漂移、脚底线漂移或 pivot 不稳。
- 同一角色跨 clip 的头部、脸、肩宽、手脚、身体长轴或武器长度明显变大/变小；倒地帧因为外接框变宽而画成更大的角色，或因为外接框变矮而缩小角色。
- 攻击动作像随机姿势拼接，装备或武器突然消失，握持手变化没有过渡，动作没有重心、蓄力、命中峰值或收招惯性。
- 任意武器、腿、爪、披风、魔法光效被裁掉，或一帧内容进入相邻 cell。
- 倒地/死亡帧因为宽度不够而把身体或魔剑裁掉，或为了塞进 cell 把角色整体缩小。
- 透明 PNG 在黑底、白底、亮粉底或棋盘格底预览时出现白边、灰边、残留矩形、半透明脏底。
- 背景过暗导致角色看不清。
- UI 图标像照片或 3D 渲染。
- 战斗/系统 UI 过度低清像素化，像农场/复古像素 UI，或与高清像素角色和特效明显割裂。
