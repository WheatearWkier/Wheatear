# 附录 04：术语表

> 本附录所属层级：**附录**
>
> 本附录目标：把教材里最容易反复出现、也最容易混淆的术语收成一份可检索的词典。
>
> 先提醒一句：这不是通用百科，而是**Wheatear 语境下的术语表**。  
> 有些词在别的引擎里也出现，但这里记录的是它在 Wheatear 这本教材里的意思。

## 4.1 怎么用这份术语表

建议你把它当成三列词典来读：

- **术语**：这个词叫什么
- **在 Wheatear 里的意思**：它在本项目里代表什么
- **常出现在哪**：你应该回头看哪一章

如果你背面试稿时卡住了，先回到这里找词，再回正文找链路。

## 4.11 调试时最容易混淆的词

### 4.11.1 `Content` 和 `State`

- `Content` 是“世界里有什么”
- `State` 是“现在走到哪了”

### 4.11.2 `Command` 和 `Event`

- `Command` 更像“请做这件事”
- `Event` 更像“这件事已经发生了”

### 4.11.3 `Scene` 和 `SceneTransition`

- `Scene` 是当前世界
- `SceneTransition` 是从一个世界到另一个世界的流程

### 4.11.4 `Settings` 和 `Progress`

- `Settings` 是用户偏好
- `Progress` 是游戏局势

### 4.11.5 `Prefab` 和 `Play Mode Copy`

- `Prefab` 是模板
- `Play Mode Copy` 是运行时副本

## 4.12 最容易被问到的几个词

### Q1：为什么 `GameProgress` 不是普通存档类？

因为它还负责当前章节、目标、结果页、解锁和场景上下文，所以它更像全局进度中枢。

### Q2：为什么 `ActionRecipe` 不直接等于技能？

因为 `ActionRecipe` 是动作的通用表达，而技能只是它在某个玩法里的落地形式。

### Q3：为什么 `CommandBus` 要独立出来？

因为它让 UI、脚本、战斗、剧情和进度之间保持解耦。

### Q4：为什么要有 `Play Mode Copy`？

因为编辑态和运行态必须隔离，不然调试和修改会互相污染。

## 4.13 小结

这份术语表的意义只有一个：

**让你在整本教材里不会被自己的名词体系绊住。**

如果你能稳定区分：

- 内容 vs 状态
- 命令 vs 事件
- 场景 vs 切换
- 模板 vs 副本
- 设置 vs 进度

那你就已经真正进入这套架构的语言体系了。
