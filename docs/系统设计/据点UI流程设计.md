# 《Wheatear 异世界项目》据点 UI 与流程策划方案 v0.1

## 0. 文档定位

本文档负责定义章节间据点 UI 的页面结构、玩家流程、数据字段、状态提示和竖切实现范围。

据点 UI 是本游戏的核心枢纽：

`VN 剧情 -> 据点 UI -> 强化 / 配装 / 好感 / 副本选择 -> 战斗 -> 结算 -> 据点 UI -> 继续剧情`

它不是传统大地图。初版应做成功能清晰、信息密度适中、可扩展、可由数据驱动的菜单型据点。

## 1. 设计目标

据点 UI 要解决以下问题：

- 玩家从剧情或战斗回来后，明确知道下一步该做什么。
- 玩家能快速强化主角、魔剑、装备和支援。
- 玩家能知道缺什么材料、材料去哪刷。
- 玩家能选择继续主线或重刷副本。
- 玩家能查看好感阶段、角色事件和支援技能。
- 玩家能配置当前战斗支援。
- 玩家能看到当前路线、剧情目标和关键标记。

设计边界：

- 初版不做可探索城镇。
- 初版不做复杂基地建造。
- 初版不做大量 NPC 管理。
- 所有功能优先服务核心循环和竖切可玩性。

## 2. 信息架构

### 2.1 顶层导航

据点 UI 顶层建议分为 8 个入口：

| 入口 | 功能 |
| --- | --- |
| 继续剧情 | 进入下一段 VN 或下一个主线副本 |
| 副本选择 | 重刷已解锁副本、查看掉落和评分 |
| 主角成长 | 查看等级、属性、经验和升级结果 |
| 魔剑技能树 | 解锁和升级技能 |
| 装备 | 穿戴、强化、对比装备 |
| 队友关系 | 查看好感、角色事件、支援等级 |
| 支援配置 | 配置战斗中可调用的支援技能 |
| 资料 / 存档 | 图鉴、剧情回放、保存、设置 |

### 2.2 常驻信息

所有据点页面建议常驻显示：

- 当前章节。
- 当前主线目标。
- 主角等级和经验进度。
- 魔剑等级。
- 金钱。
- 关键材料数量。
- 当前队伍支援头像。
- 继续剧情按钮。

常驻信息不要过多，更多细节进入对应页面查看。

### 2.3 通知系统

据点 UI 需要清楚提示玩家有哪些新内容：

| 通知类型 | 出现位置 | 示例 |
| --- | --- | --- |
| 新技能可解锁 | 魔剑技能树入口 | 有技能满足条件 |
| 装备可强化 | 装备入口 | 当前材料足够强化 |
| 新角色事件 | 队友关系入口 | 白魔法队友信赖事件可触发 |
| 新副本解锁 | 副本选择入口 | 黑林兽道已解锁 |
| 主线可继续 | 继续剧情入口 | 前往边境村 |
| 支援槽可配置 | 支援配置入口 | 新支援技能可装备 |

通知只负责提示，不应强制玩家立刻处理。

## 3. 页面流程

### 3.1 从 VN 进入据点

流程：

1. VN 场景设置剧情标记。
2. 系统检查是否应进入据点。
3. 据点读取 `HubEntryPayload`。
4. 显示新解锁内容和当前目标。
5. 玩家选择强化、刷本或继续剧情。

`HubEntryPayload` 建议字段：

| 字段 | 说明 |
| --- | --- |
| `FromScene` | 来源场景 |
| `ChapterId` | 当前章节 |
| `SetFlags` | 新增剧情标记 |
| `NewUnlocks` | 新解锁的副本、技能、角色事件 |
| `SuggestedAction` | 推荐下一步 |
| `NarrativeSummary` | 简短剧情摘要 |

### 3.2 从战斗结算进入据点

流程：

1. 战斗结束。
2. 显示结算页面。
3. 玩家确认经验、材料、装备、评分和剧情变量。
4. 奖励写入存档。
5. 返回据点首页。
6. 据点刷新可强化、可解锁、可继续内容。

结算必须显示：

- 副本名称。
- 通关时间。
- 最大连击。
- 断限成功次数。
- 评分。
- 获得经验。
- 获得材料。
- 获得装备。
- 首通奖励。
- 新解锁内容。

### 3.3 继续剧情

继续剧情按钮逻辑：

| 状态 | 行为 |
| --- | --- |
| 主线 VN 可进入 | 跳转目标 VN 场景 |
| 主线副本可进入 | 打开主线副本确认 |
| 推荐等级不足 | 显示推荐等级和可刷副本 |
| 前置事件未完成 | 跳转对应角色事件或提示 |
| 数据缺失 | 显示错误并阻止跳转 |

继续剧情不应隐藏在多个菜单深处，它应该始终可见。

## 4. 首页布局

首页推荐结构：

| 区域 | 内容 |
| --- | --- |
| 顶部状态栏 | 章节、目标、等级、资源 |
| 左侧导航 | 8 个顶层入口 |
| 中央主区域 | 当前目标、推荐行动、新解锁 |
| 右侧队伍栏 | 队友头像、好感阶段、支援冷却预览 |
| 底部操作栏 | 继续剧情、保存、返回标题 |

首页核心卡片：

- 当前主线：下一步去哪，推荐等级多少。
- 可强化：哪些装备或技能已经满足条件。
- 可刷副本：当前最推荐刷哪个副本，掉什么关键材料。
- 角色事件：哪个角色有新事件。

注意：

- UI 文案要简洁，不写长说明。
- 页面不要做成宣传页。
- 所有入口都要能用手柄或键盘方向键切换。
- 重要操作需要确认，普通查看不需要确认。

## 5. 副本选择页

### 5.1 列表信息

副本列表每项显示：

- 副本名。
- 类型：主线、材料、试炼、Boss 复战。
- 推荐等级。
- 首通状态。
- 历史最高评分。
- 主要掉落。
- 推荐支援。
- 核心机制标签。

示例：

| 副本 | 类型 | 推荐 | 掉落 | 机制 |
| --- | --- | --- | --- | --- |
| 黑林兽道 | 材料 | Lv 4 | 兽爪、初级魔核、黑林装备 | 上挑、短空连、远程躲避 |
| 魔剑觉醒 | 主线回放 | Lv 5 | 黑熊材料、初级饰品 | 基础 Boss、火球补 hit |

### 5.2 详情页

副本详情必须显示：

- 副本简介。
- 推荐等级和玩家当前等级。
- 推荐装备。
- 推荐支援。
- 主要敌人。
- Boss。
- 首通奖励。
- 重刷奖励。
- 可能掉落装备。
- 当前缺失材料是否可在此副本获得。

### 5.3 进入确认

进入副本前玩家可以：

- 调整支援配置。
- 查看掉落。
- 查看推荐技能。
- 直接开始。
- 返回据点。

如果推荐等级不足，允许进入，但显示“挑战较难”的提示。不要硬锁，除非剧情不允许。

## 6. 魔剑技能树页

### 6.1 页面目标

魔剑技能树页面要让玩家理解三件事：

- 现在能解锁什么。
- 解锁后战斗中怎么用。
- 缺的材料或好感去哪获得。

### 6.2 节点信息

每个技能节点显示：

- 技能名。
- 分支：近战、魔法、融合、机动、断限。
- 主动 / 被动 / 派生。
- 是否可空中使用。
- 连招职责。
- 材料需求。
- 等级需求。
- 魔剑等级需求。
- 好感需求。
- 祝福需求。
- 前置技能。
- 解锁后的快捷配置入口。

锁定原因必须具体：

- 缺 `兽爪 3/5`。
- 白魔法队友好感需要 70，当前 55。
- 未获得朱雀祝福。
- 前置技能未解锁。

### 6.3 与副本联动

如果缺材料，技能树应提供“来源”入口：

- 点击材料 -> 显示可掉落副本。
- 选择副本 -> 跳到副本详情。
- 打完副本 -> 回到据点并提示是否继续解锁技能。

这是避免玩家迷路的关键。

## 7. 装备页

### 7.1 页面结构

装备页分为：

- 当前装备。
- 背包装备列表。
- 属性对比。
- 强化面板。
- 材料来源。
- 词条说明。

### 7.2 装备对比

装备对比必须显示：

- HP、MP、SP、ATK、MATK、DEF、MDEF 变化。
- 支援冷却变化。
- 空中伤害变化。
- 断限窗口变化。
- 保护条压制变化。
- 抗性变化。
- 套装效果是否激活。

装备变化要尽量用数字和图标表示，不用大段文本。

### 7.3 强化流程

强化流程：

1. 选择装备。
2. 显示当前等级和强化上限。
3. 显示消耗材料。
4. 显示强化后属性变化。
5. 玩家确认。
6. 播放简短反馈。
7. 更新属性和通知。

缺材料时：

- 显示缺少数量。
- 提供材料来源副本入口。
- 不允许误点消耗不存在的材料。

## 8. 队友关系页

### 8.1 页面结构

队友关系页显示：

- 角色头像。
- 角色名称或代号。
- 好感值。
- 信赖阶段。
- 当前支援等级。
- 下一级支援效果。
- 可触发事件。
- 魔剑技能关联。
- 后宫确认状态。

### 8.2 事件入口

角色事件状态：

| 状态 | UI 行为 |
| --- | --- |
| 未解锁 | 显示锁定原因 |
| 可触发 | 显示新事件提示 |
| 已完成 | 可回放 |
| 关键事件 | 显示主线相关标记 |

事件触发后可能进入：

- VN 对话场景。
- 小型战斗。
- 副本入口。
- 直接回据点。

### 8.3 青梅特殊处理

第一部终章前：

- 不显示“青梅正宫好感”。
- 只显示导师相关提示或隐藏状态。
- 如果显示导师，应避免暴露真实身份。

第一部终章后：

- 解锁青梅正宫页面。
- 显示誓约支援。
- 显示与断限和空界连锁的关联。

第十二章后：

- 王妃 / 天使页面完整开放。

## 9. 支援配置页

### 9.1 配置内容

玩家可以配置：

- 主动支援槽 1。
- 主动支援槽 2。
- 主动支援槽 3。
- 誓约被动槽。
- 组合奥义槽。

初版竖切只需要主动支援槽的基础结构。

### 9.2 支援详情

支援详情显示：

- 支援名。
- 角色。
- 类型：治疗、护盾、攻击、破防、控场、净化、复活。
- 冷却。
- 当前好感加成。
- 连招接口。
- 空中是否可用。
- 对 Boss 的效果衰减。

### 9.3 推荐配置

副本详情可以给推荐支援：

- 新手副本：导师提示或保命支援。
- 白魔法章节：治疗 / 护盾。
- 剑盾章节：格挡 / 聚怪。
- 黑魔法章节：破防 / 控场。
- 七大罪：按机制推荐。

推荐不等于强制。玩家可以尝试其他配置。

## 10. 主角成长页

显示：

- 当前等级。
- 经验进度。
- ATK、MATK、DEF、MDEF、HP、MP、SP。
- 装备加成。
- 魔剑加成。
- 支援被动加成。
- 下一等级预览。

升级规则：

- 经验满后可自动升级。
- 据点显示升级结果。
- 不需要玩家手动分配基础点数，初版避免复杂。
- 后续如果需要，可以加入“成长偏向”系统，但不放进竖切。

## 11. 路线确认与资料页

路线确认显示：

- 当前主线目标。
- 已完成章节。
- 已解锁副本。
- 未完成角色事件。
- 关键剧情标记。
- 当前世界状态。

资料页显示：

- 敌人图鉴。
- 材料图鉴。
- 装备图鉴。
- 剧情回放。
- 教学回看。
- 设置和存档。

教学回看很重要，因为战斗系统有空连、断限、支援和保护条，玩家需要能回看。

### 12.4 RelationshipState

引用 [好感与支援设计](好感与支援设计.md) 中的关系数据。

### 12.5 竖切当前落地

当前工程先用 `Wheatear/src/Wheatear/Modules/Progression/` 承载竖切内存进度，先保证核心循环可以玩通：

| 策划状态 | 当前代码落地 |
| --- | --- |
| `HubState.CurrentChapter` | `GameProgress::State.CurrentChapter` |
| `HubState.CurrentObjectiveId` | 当前先用 `GameProgress::State.Objective` 文本表达 |
| `HubState.UnlockedDungeons` | `GameProgress::State.UnlockedDungeons` |
| `HubState.CompletedDungeons` | `GameProgress::State.CompletedDungeons` |
| `HubState.BestRanks` | 当前先记录 `BestCombosByDungeon`，评分系统后补 |
| `HubState.StoryFlags` | `GameProgress::State.StoryFlags` |
| `PlayerProgress.Level / Experience / Attributes` | `GameProgress::State.PlayerLevel / Experience / Attributes` |
| `PlayerProgress.MagicSwordLevel` | `GameProgress::State.MagicSwordLevel` |
| `InventoryState.Materials` | `GameProgress::State.Materials` |

竖切已经接入的命令：

| 命令 | 行为 |
| --- | --- |
| `progression:upgrade_magic_sword` | 消耗 `魔核碎片 x1 / 兽筋 x2 / 熊爪 x1`，把魔剑升到 Lv2，提升 ATK / MATK，并解锁基础强化标记 |
| `progression:upgrade_traveler_armor` | 消耗 `兽筋 x1 / 熊爪 x1`，把旅人护衣强化到 +1，提升 HP / DEF |

当前版本不做磁盘存档，进度只在一次运行中保留。后续正式化时，`GameProgress` 应成为 `SaveGame / Inventory / Equipment / Relationship` 的门面或临时适配层，而不是永久把所有系统都堆在一个类里。

## 13. 场景跳转

据点 UI 的跳转必须全部数据化。

| 来源 | 条件 | 目标 |
| --- | --- | --- |
| 序章 VN 完成 | `Flag_PrologueComplete` | 第一章假玩法 |
| 第一章完成 | `Flag_CH01Complete` | 第二章 VN / 正式教程 |
| 第二章 Boss 击败 | `Flag_CH02_BossDefeated` | 据点首页 |
| 据点继续剧情 | `CurrentObjective = CH03_Start` | 第三章 VN |
| 副本选择 | 已解锁副本 ID | 对应战斗场景 |
| 副本结算 | 通关或失败 | 据点首页或重试 |

每个跳转都应设置：

- 目标场景。
- 入场参数。
- 返回场景。
- 写入剧情标记。
- 打包资源标签。

## 14. 竖切 UI 范围

第一个竖切只做以下页面：

- 首页。
- 继续剧情。
- 副本选择。
- 战斗结算。
- 魔剑技能树简版。
- 装备简版。
- 支援配置占位。
- 队友关系占位。
- 保存 / 载入基础入口。

竖切不做：

- 完整图鉴。
- 装备重铸。
- 多角色完整好感。
- 组合奥义配置。
- 复杂动画演出。
- 可探索据点。

## 15. 竖切验收标准

玩家必须能完成：

1. 从第二章正式教程打赢黑熊丈夫。
2. 进入战斗结算。
3. 查看获得的经验、材料和装备。
4. 回到据点首页。
5. 查看当前主线目标。
6. 打开魔剑技能树。
7. 用黑熊材料解锁或升级一个基础技能。
8. 打开装备页。
9. 穿戴或强化一件装备。
10. 打开副本选择。
11. 进入黑林兽道重刷。
12. 结算后回到据点。
13. 点击继续剧情进入第三章入口。

如果这条链路稳定，核心循环就成立。

## 16. 编辑器落地建议

未来 WheatearEditor 可以把据点 UI 拆成以下资源：

| 资源 | 用途 |
| --- | --- |
| `HubDefinition` | 据点页面、入口、默认目标 |
| `HubActionDefinition` | 每个按钮行为 |
| `ObjectiveDefinition` | 当前目标和跳转 |
| `NotificationRule` | 新内容提示规则 |
| `PanelLayoutDefinition` | 页面布局和控件绑定 |
| `SceneTransitionDefinition` | 场景跳转 |

数据校验：

- 继续剧情必须有合法目标。
- 副本入口必须引用存在的 `DungeonDefinition`。
- 技能树材料来源必须能找到副本。
- 装备材料来源必须能找到副本。
- 好感事件必须能找到场景或脚本。
- 所有 UI 图标必须进入打包资源引用。

## 17. 后续实现顺序

建议实现顺序：

1. 据点状态数据。当前竖切已用 `GameProgress` 完成内存版。
