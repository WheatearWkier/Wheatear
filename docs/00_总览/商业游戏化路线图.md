# 《Wheatear 异世界项目》商业游戏化路线图 v0.3

## 0. 文档定位

本文档是后续制作的主路线。它不替代总纲、战斗设计、据点 UI、关卡副本和竖切实现记录，而是回答一个更实际的问题：

**我们接下来怎么一步一步把当前竖切做成“像完整商业游戏一样能玩、能看、能扩展、能打包交付”的作品。**

后续所有新功能都按本文档的优先级推进。总原则是：先补系统完整性，再统一美术资源，最后统一音频表现。当前已经有第一轮占位 BGM 和战斗音效，用于验证流程和反馈，后续仍要按最终美术节奏整体升级。

## 1. 总推进顺序

```text
系统完整性
-> 统一美术资源升级
-> 音频与反馈升级
-> 内容扩章与商业化打磨
```

### 1.1 第一阶段：系统完整性

这一阶段不追求最终美术质量，但每个功能都必须真实可见、可操作、可验证。

标准不是“代码写了”，而是：

- 玩家能在场景里看到这个页面或功能。
- 玩家能点击、选择、战斗、返回或继续。
- 页面有临时但像样的 UI 素材，不再用纯方块糊弄功能。
- 数据变化能显示出来，例如经验、材料、装备、技能、好感。
- 打包后的 `WheatearSandbox` 能加载并运行。
- 文档同步记录实现边界和下一步。

### 1.2 第二阶段：统一美术资源升级

当系统闭环稳定后，再集中替换美术。这样不会因为页面还在改，导致美术资源反复报废。

本阶段重点：

- 制定统一美术风格规范。
- 替换 VN 立绘、表情差分、背景和 CG。
- 替换战斗角色、敌人、Boss、武器、技能特效和受击动画。
- 统一据点、结算、技能树、装备页、战斗 HUD 的 UI 风格。
- 保留当前像素 UI 作为低成本可用底稿，后续按同名资源或映射表替换。

### 1.3 第三阶段：音频与反馈升级

音频的最终品质升级放在美术之后做，原因是音效和 BGM 需要跟最终画面节奏、技能演出和 UI 动效对齐。当前竖切已经先接入占位 BGM、战斗音效、音量滑条和打包验证，用于保证系统链路可用。

本阶段重点：

- VN 日常、紧张、战斗前、反转剧情 BGM。
- 战斗普通攻击、上挑、跳斩、火球、断限追击、Boss 招式音效。
- UI 点击、确认、解锁、强化、结算奖励音效。
- 受击、破防、浮空、落地、掉落、评分结算反馈。
- 音量设置、分组混音和打包校验。

## 2. 当前竖切状态

当前已经证明的核心闭环：

```text
主菜单
-> VN 剧情
-> 第一章假玩法
-> 回合制魔剑试炼
-> 第二章正式 SideCombat
-> Boss 战
-> 战斗结算页
-> 据点页
-> 魔剑技能树页
-> 装备强化页
-> 副本选择 / 好感关系 / 支援配置 / 存读档 / 设置
-> 重刷副本 / 继续剧情
-> 打包运行
```

当前已经具备的工程基础：

- `VisualNovel`、`ArcadeCombat`、`TurnCombat`、`SideCombat`、`Progression` 等模块已经从引擎基础 `Systems` 中分离。
- 回合制战斗已经作为假玩法和正式横板战斗之间的过渡模块接入：斜向站位、底部命令栏、目标选择、行动顺序、技能说明、角色状态条、动画帧、BGM 和 SFX 已有竖切版。
- 战斗参数已经通过 `side_combat_tuning.yaml` 暴露，便于调跳跃、击飞、滞空、受击保护等手感参数。
- `Side Combat Tuning Editor` 已接入编辑器，可用页签直接调手感、规则、招式、技能和关卡 profile。
- `VN Script Editor` 已接入编辑器，可在时间线里维护台词、人物、表情、背景、BGM、选择项和跳转。
- VN 已支持 `@music` / `@bgm` 切换循环 BGM，并有左上角曲名提示动画。
- 打包流程已经使用 `.wtpack` 收集引用资源，而不是复制整个 `assets`。
- 据点、结算、技能树、装备页、副本选择、好感关系、支援配置、存读档、设置页已经有独立场景和临时 UI 素材。
- UI 动效已经通过 `UIAnimatorComponent` 接入，可用于面板入场、结算弹出、按钮呼吸等表现。
- UI 文字已经支持阴影和描边字段，VN 与据点文字不再只依赖单层细字显示。
- 魔剑技能树已经升级为专用 `UISkillTreeViewComponent`：圆环/螺旋分支、图标节点、曲线连线、拖动画布、裁剪视口和选中详情面板都走同一个可复用控件。
- 装备页已经有第一版装备槽、背包图标网格、分页按钮、页码滑条和选中详情面板。
- VN 指令栏保存 / 读取已经改为打开存读档覆盖层，VN 内一号槽会同时保存剧情位置和竖切成长进度。
- 设置页已经有文本速度和主音量滑条显示。
- `Progression` 已具备竖切用磁盘存读档、好感关系、支援选择和基础设置状态。

当前还不能称为完整商业游戏，因为缺少：

- 正式多槽存档 UI、自动存档策略、失败恢复和更完整的读档信息。
- 更正式的背包、装备实例、好感事件、支援槽位和资料图鉴系统。
- VN 历史记录、自动播放、快进等常见 Galgame 功能；VN 保存 / 读取入口已有一号槽竖切版，但还不是正式多槽系统。
- 更完整的战斗教程、敌人类型、Boss 机制提示、失败 / 胜利流程。
- 统一美术、角色动画、技能特效和音频反馈。

## 3. 系统完整性清单

### 3.1 主流程和存档

必须完成：

- 新游戏：清空旧进度，进入序章。
- 继续游戏：读取最近存档，回到上次场景或据点。
- 自动存档：章节节点、战斗结算、据点操作后写入。
- 手动存档：VN 和据点可打开存档页。
- 读档页：显示章节、时间、主角等级、当前目标。
- 失败恢复：战斗失败后可重试、回据点或读档。

验收标准：

- 关闭游戏后重新打开，能继续竖切进度。
- 打完 Boss 后获得的材料、技能、装备不会丢。
- 打包版和编辑器运行版表现一致。

### 3.2 据点 UI

必须完成：

- 首页：当前目标、主角状态、材料摘要、下一步入口。
- 副本选择：主线副本、材料副本、推荐等级、主要掉落、重刷入口。
- 结算页：评分、连击、经验、材料、装备、首通奖励、继续入口。
- 魔剑技能树：技能节点、材料需求、好感条件、已解锁状态。
- 装备页：装备槽位、强化等级、属性变化、材料消耗。
- 好感页：队友好感、支援技能等级、下一阶段条件。
- 支援配置页：当前支援槽、技能说明、冷却和好感收益。
- 设置页：显示、音量、按键、文本速度等基础选项。

验收标准：

- 每个页面都有临时 UI 素材和清晰布局。
- 每个按钮都有真实行为或明确的锁定状态。
- 成长资源不足时能告诉玩家缺什么、去哪刷。
- 页面切换有基础动画，不突兀闪屏。

### 3.3 VN 系统

必须完成：

- 对话推进、选项、角色名、立绘、表情差分。
- 历史记录页面。
- 自动播放和快进。
- VN 中保存 / 读档。
- 场景跳转和剧情标记。
- 背景切换、角色进出场、简单转场动画。

验收标准：

- 玩家能完整阅读序章到第三章入口。
- 表情差分能看出变化。
- 跳转不会丢剧情状态。
- 打包后字体、立绘、背景都能显示。

### 3.4 SideCombat 战斗

必须完成：

- 俯视感横板战斗视角。
- 移动、一段跳、闪避、普攻、上挑、跳斩、火球、基础支援。
- 空中攻击逐步下落，滞空由技能和参数控制。
- 敌人浮空或被控制时只播放受击 / 控制状态，不继续正常攻击。
- Boss 保护条、浮空保护、普通打法可过、高手空连更快。
- 断限追击作为高级机制预留或局部上线。
- 战斗 HUD、教程提示、连击显示、Boss 血条、奖励提示。

验收标准：

- 普通玩家不用断限也能打赢竖切 Boss。
- 熟练玩家能通过跳斩、上挑、火球打出空中连击。
- 参数表能调整跳跃高度、击飞高度、滞空、重力、伤害、冷却。
- 受击、命中、击飞、落地都有可见反馈。

### 3.5 成长和经济

必须完成：

- 主角等级、经验、基础属性。
- 材料背包。
- 装备获得、穿戴、强化。
- 魔剑等级和技能树。
- 好感度和支援技能等级。
- 副本首通奖励、重刷奖励、保底奖励。

验收标准：

- 玩家打副本能稳定得到成长资源。
- 成长能直接改变战斗表现或 UI 状态。
- 关键剧情材料首通必给，重刷材料有目标。
- 好感不需要刷材料，但会提升支援强度和技能条件。

### 3.6 编辑器和打包

必须完成：

- 场景引用资源校验。
- 数据表引用校验。
- 打包前缺资源提示。
- `.wtpack` 只包含引用资源。
- 打包后场景、贴图、字体、数据表、配置文件都能读取。
- 打包版可运行完整竖切验收流程。

验收标准：

- 打包目录不超过合理体积。
- 不再把整个 `assets` 目录搬进 `Builds`。
- 缺资源时编辑器给出可理解的错误。
- 竖切主流程和关键页面都能在打包版打开。

## 4. 统一美术资源路线

在系统完整性达标后再进入本阶段。

### 4.1 美术规范

先确定：

- 画面比例和目标分辨率。
- VN 立绘尺寸、表情差分命名、角色站位。
- 战斗 Sprite 尺寸、帧率、动作表。
- 技能特效尺寸、层级和透明规则。
- UI 面板、按钮、图标、徽章、进度条风格。
- 文件命名、目录分类和资源 ID 映射。

### 4.2 替换顺序

推荐顺序：

1. VN 主角相关立绘、青梅、导师、假青梅。
2. SideCombat 主角战斗 Sprite 和魔剑攻击特效。
3. 小怪、黑熊丈夫 Boss、投射物、掉落物。
4. 据点、结算、技能树、装备页 UI 皮肤。
5. 背景、场景物件、远景和前景遮挡。
6. CG、章节插图和宣传用图。

当前生成的像素 UI 可以继续作为竖切底稿。后续替换时优先保持资源路径稳定，避免反复改场景引用。

## 5. 音频路线

音频最终版在系统和美术稳定后集中接入；当前第一轮占位音频已经用于验证 VN BGM、战斗音效、音量设置和打包链路。

必须完成：

- 音频资源目录规范。
- BGM 切换规则：VN 已支持 `@music` / `@bgm`，其他模式后续继续补统一 Audio Cue。
- UI 音效。
- 战斗命中、受击、闪避、技能、Boss 招式音效。
- 结算、掉落、升级、解锁音效。
- 音量设置和静音。

验收标准：

- 打包版能播放音频。
- UI、VN、战斗音量可独立调整。
- 音效不会重复爆音。
- 战斗关键反馈能通过声音被玩家识别。

## 6. 功能完成定义

以后每做一个功能，都必须同时满足：

- 策划：文档说明清楚用途、规则、验收方式。
- 数据：有可维护的数据字段或配置表。
- 代码：职责放在正确模块，不混入无关引擎基础系统。
- 场景：有真实场景或页面承载功能。
- 素材：至少有临时但可辨认的图像、图标或动画。
- 交互：玩家可以看到状态变化，并能做出操作。
- 打包：打包版可以加载相关资源。
- 记录：实现记录和索引同步更新。

一句话标准：**玩家看不到、点不到、玩不到、打包版跑不到，就不算完成。**

## 7. 近期执行路线

### 7.1 已完成到竖切可验证

1. 据点系统页面第一轮补齐：副本选择、好感关系、支援配置、保存 / 读取、设置。
2. 据点首页导航扩展为完整系统入口，并接入黑林兽道材料本。
3. `GameProgress` 支持竖切用存档文件、好感关系、支援选择和设置状态。
4. VN 文本速度接入全局设置，UI 文本接入阴影和描边改善可读性。
5. 技能树、装备页、设置页和存读档页完成第一轮图标化 UI 打磨。
6. VN 内保存 / 读取覆盖层已接入，能保存 / 读取一号槽剧情位置和成长进度。
7. 打包版已验证关键系统页面和黑林兽道场景可加载。

### 7.2 下一轮优先级

当前建议先做这些：

1. 完善 VN 通用 UI：历史记录分页、自动播放、快进、正式多槽存档和读档信息。
2. 打磨 SideCombat 教程、HUD、连击提示、受击反馈、失败 / 胜利流程。
3. 将技能树、装备页和背包继续推进到可高亮选中、可查看来源、可翻页管理、可明确锁定原因。
4. 将设置页从“状态记录”推进到“真实作用”：音量混音、窗口 / 全屏、按键映射。
5. 把更多常用战斗和 UI 参数暴露到 YAML，并保证打包版能读取。
6. 补编辑器校验：场景跳转、资源引用、配置文件、`.wtpack` 内容。
7. 做一次“打包版完整竖切验收”，按玩家流程从主菜单跑到第三章入口。

这些完成后，系统完整性第一阶段就基本达标，再进入统一美术资源升级。

## 8. 文档维护规则

- 新增路线或改变优先级时，先更新本文档。
- 新增系统规则时，更新对应系统设计文档。
- 新增场景、素材、数据文件时，更新竖切工程实现记录。
- 改动可玩流程时，更新竖切实现清单和据点 UI 流程。
- 新增文档时，必须同步更新 [文档入口](../文档入口.md)。
- 不再保留已经过时的“简版”描述；如果功能还不完整，写清楚“当前已实现”和“后续待完善”。
