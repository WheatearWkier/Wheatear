## WheatearEditor 操作手册

更新日期：2026-07-30

本文记录 WheatearEditor 当前已经能使用的主要操作。目标是让策划、美术、程序都能直接打开编辑器调整场景、UI、VN 剧本、战斗参数和打包流程，而不是每次都依赖代码生成 YAML。

### 1. 启动编辑器

#### 1.1 直接打开

构建后的编辑器位于：

```text
Builds/Windows/Editor/WheatearEditor.exe
```

直接双击即可打开，不需要每次从 Visual Studio 里启动。

#### 1.2 重新构建编辑器

在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Build-WheatearEditor.ps1
```

脚本会构建 `WheatearEditor`，并把可运行编辑器复制到：

```text
Builds/Windows/Editor/WheatearEditor.exe
```

#### 1.3 选择编辑模式

启动后会先进入模式选择界面：

- `2D Mode`：用于 2D 场景、Sprite、UI、VN、横板战斗、动画编辑。
- `3D Mode`：用于 3D Mesh、PBR/IBL、灯光相关内容。

当前竖切游戏内容主要使用 `2D Mode`。

### 2. 布局和设置保存

编辑器窗口使用 ImGui Docking。你可以把 `Scene Hierarchy`、`Properties`、`Viewport`、`Content Browser`、`Animation Editor`、`UI Canvas Editor` 拖到自己习惯的位置。

布局配置不再跟随 `Builds` 目录里的 exe 重置，而是保存到：

```text
%LOCALAPPDATA%/Wheatear/Wheatear Editor/imgui.ini
```

重新构建或覆盖 `Builds/Windows/Editor/WheatearEditor.exe` 后，子面板布局仍然会保留。若布局被拖乱，可以关闭编辑器后删除上面的 `imgui.ini`，下次启动会恢复默认布局。

首次启动且没有已有 `imgui.ini` 时，编辑器会自动铺一套默认 Docking 布局：左侧 Hierarchy，右侧 Properties，中间 Viewport，底部 Content Browser 和 Animation Editor。已有自定义布局时不会被自动覆盖。

如果想主动回到默认布局，可以点击：

```text
View / Reset Window Layout
```

### 3. 菜单栏

#### 3.1 File

- `New`：新建空场景。
- `Open...`：打开 `.wt` 场景文件。
- `Save`：保存当前场景。
- `Save As...`：另存当前场景。
- `Package Player`：打包运行版，不主动携带 C# 游戏脚本程序集。
- `Package Player With C# Scripts`：打包运行版，并携带 C# 脚本程序集。
- `Open Build Folder`：打包成功后打开本次构建输出目录。
- `Exit`：关闭编辑器。

打包前请先保存场景。未保存的场景不会作为稳定入口参与打包。

#### 3.2 Edit

- `Undo`：撤销，快捷键 `Ctrl+Z`。
- `Redo`：复原，快捷键 `Ctrl+Y` 或 `Ctrl+Shift+Z`。

当前撤销/复原覆盖常用编辑行为：创建实体、删除实体、复制实体、添加组件、移除组件、重置组件、Inspector 字段修改、Viewport Gizmo 移动/旋转/缩放、UI 控件拖动和缩放。

#### 3.3 View

- `Focus Primary Camera`：把编辑器视角归位到当前场景的运行时主 Camera，并在 Hierarchy 中选中它。
- `UI Edit Outlines`：显示或隐藏 UI 控件编辑边框。
- `Hide UI In Scene Viewport`：在主 Viewport 暂时隐藏 UI，方便编辑被 UI 挡住的场景物体。
- `UI Canvas Editor`：打开专属 UI 编辑视窗。
- `Sprite Sheet Picker`：打开图集选择器，用于选择 atlas 子图或切割连续动画帧。
- `Physics Colliders`：显示或隐藏物理碰撞体辅助线。
- `Reset Window Layout`：重置编辑器窗口停靠布局。

### 5. Scene Hierarchy

`Scene Hierarchy` 是场景实体列表。

#### 5.1 搜索和过滤

- 顶部搜索框可以按实体名过滤。
- `UI` 复选框只显示带 `UIWidgetComponent` 的 UI 实体。
- 如果当前选中实体被搜索条件隐藏，面板会提示 `Selected entity is hidden by filters`，可点击 `Clear Hierarchy Filters` 清空过滤。

#### 5.2 实体类型前缀

列表中会显示简单类型前缀：

- `[UI]`：UI 控件或 Canvas。
- `[Camera]`：相机。
- `[3D]`：3D Mesh。
- `[2D]`：Sprite 或 Circle。
- `[Entity]`：普通实体。

#### 5.3 创建实体

在空白区域右键：

- `Create Empty Entity`：创建空实体。
- `2D Object / Sprite`：创建 2D Sprite。
- `2D Object / Circle`：创建圆形渲染实体。
- `Camera / Camera`：创建相机。
- `UI / Canvas`：创建 UI Canvas。
- `UI / Panel`：创建 UI 面板。
- `UI / Image`：创建 UI 图片。
- `UI / Text`：创建 UI 文本。
- `UI / Button`：创建按钮。
- `UI / Slider`：创建滑条。
- `UI / Checkbox`：创建复选框。
- `UI / Progress Bar`：创建进度条。
- `UI / Templates`：创建可复用 UI 模板，例如分页网格、装备格子、Tooltip、存档槽、技能树节点和战斗技能槽。

正式 UI 页面必须先创建 `UI / Canvas`。`Panel`、`Image`、`Text`、`Button`、`Slider`、`Checkbox`、`Progress Bar` 只有在当前选中 Canvas 或已经属于某个 Canvas 的 UI 子控件时才可创建。

创建 UI 子控件时，新控件会自动把 `Parent Tag` 设置为当前选中控件的名字。这样新 UI 会挂在当前 Canvas/父控件下面，并使用父区域内的局部坐标。

#### 5.4 UI 父子层级

UI 父子关系通过 `UIWidgetComponent.ParentEntity` 保存为 UUID。Hierarchy 会把子 UI 缩进显示在父 UI 下方，Canvas 下的控件会像树一样展开。

当前规则：

- 子控件的位置和尺寸是父控件区域内的归一化坐标。
- 父控件隐藏时，子控件也会被视为隐藏。
- 如果父控件是带裁剪的 `UIPanelComponent`，运行时和编辑预览会按父区域裁剪子控件。
- 如果 `Parent Tag` 写错或父实体改名，子控件会变成孤儿，需要在 Inspector 里重新设置。

#### 5.5 右键实体操作

对实体右键：

- `Rename`：重命名实体。
- `Duplicate Entity`：复制实体。
- `Save as Prefab`：保存为 `.wtprefab`。
- `Delete Entity`：删除实体。

删除、复制、创建都进入撤销栈，可以用 `Ctrl+Z` 撤销。

### 6. Properties / Inspector

右侧 `Properties` 面板显示当前选中实体的组件。

#### 6.1 重命名

面板顶部是实体名输入框。也可以在 Hierarchy 右键实体选择 `Rename`，编辑器会自动把键盘焦点放到这个输入框。

#### 6.2 Add Component

点击 `Add Component` 可以添加组件。当前组件分类包括：

- `Core`：基础组件，例如 Transform。
- `Rendering`：Camera、Sprite Renderer、Sprite Animator、Circle Renderer、Mesh Renderer。
- `Lighting`：Directional Light、Point Light。
- `Physics`：Rigidbody 2D、Box Collider 2D、Circle Collider 2D。
- `Scripting & Audio`：Script、Event Script、Audio Source。
- `UI`：UI Canvas、UI Widget、UI Animator、UI Image、UI Panel、UI Text、UI Button、UI Progress Bar、UI Slider、UI Checkbox。
- `Visual Novel`：视觉小说流程组件。
- `Side Combat`：横板战斗关卡、角色、玩家控制、敌人 AI、Hitbox、Pickup。
- `Arcade Combat`：早期类坦克大战模块，可保留给假玩法或特殊关卡。

添加 UI 表现类组件时，目标实体必须是 Canvas 或 Canvas 下的 UI 子控件。`UIWidgetComponent` 是每个 UI 控件的布局基础，Canvas 自身也需要一个 Widget 作为全屏根节点；普通场景实体不能再通过 Inspector 随意补 UI 表现组件。

#### 6.3 组件 Reset 和 Remove

每个可编辑组件右上角都有组件菜单：

- `Reset`：重置组件到默认值。
- `Remove Component`：移除组件。

这些操作会进入撤销栈。

#### 6.4 Event Script

`Event Script` 是 Wheatear 原生 `.wts` 事件脚本组件，适合做按钮流程、剧情分发、结算跳转和简单条件事件。

常用字段：

- `Script Path`：`.wts` 文件路径，例如 `assets/events/vertical_slice_flow_sample.wts`。
- `Start Event`：默认启动事件名，通常是 `on_start`。
- `Enabled`：是否启用。
- `Run On Start`：场景运行时是否自动执行 `Start Event`。
- `Run Once`：同一组件生命周期内是否只执行一次。

按钮触发事件的写法：

```text
event:open_skill_tree
```

其中 `open_skill_tree` 是 `.wts` 文件里的事件名。默认写法会广播给当前场景的事件脚本；如果同场景有多个流程控制实体，可以使用 `event:@<UUID>:open_skill_tree` 精确指定目标。

`.wts` 中可以写：

```text
event open_skill_tree:
    scene:assets/scenes/VerticalSliceSkillTree.wt
end
```

`scene:`、`newgame:`、`loadgame:` 命令会进入引擎的 `SceneTransitionService`，再由当前运行宿主执行实际加载。

点击 `Open Event Graph` 可以打开当前脚本的可视化流程图。也可以从顶部菜单 `View / Event Script Graph` 打开。第一版流程图用于查看和排查：它会显示事件开始、命令、等待、条件范围和源行号；修改脚本仍然在组件下方的 `.wts` 文本编辑器中完成并保存。

### 7. Viewport

`Viewport` 是主场景编辑窗口。

#### 7.1 选中实体

在 Viewport 中点击可选中场景实体。选中后，左侧 Hierarchy 会高亮并滚动到对应实体。

如果当前打开了 UI 编辑轮廓，点击 UI 控件也会选中对应 UI 实体。按住 `Alt` 操作相机时会避免误选 UI。

#### 7.2 Gizmo

普通场景实体选中后可以使用 Gizmo：

- `W`：移动。
- `E`：旋转。
- `R`：缩放。
- `Q`：关闭 Gizmo。

拖拽 Gizmo 完成后会生成一条撤销记录。按住 `Ctrl` 拖拽时使用吸附。

#### 7.3 归位到运行时相机

在 Viewport 内双击左键，编辑器相机会对齐到当前场景的 `Primary` Camera 的位置和朝向。Hierarchy 会同时选中这个 Camera 实体，表示当前编辑器视角正在参考它。

注意：编辑器相机仍保持自己的透视编辑投影，不会因为运行时 Camera 是正交相机就把编辑器视窗切成正交模式。这样归位之后继续右键拖动视窗，操作手感仍和原本编辑器相机一致。

也可以使用菜单：

```text
View / Focus Primary Camera
```

#### 7.4 拖放资源

从 `Content Browser` 把 `.wt` 场景拖到 Viewport，可打开该场景。

从 `Content Browser` 把 `.wtprefab` 拖到 Viewport，可实例化 Prefab。

从 `Content Browser` 把 `.wtuit` 拖到 Viewport，可实例化 UI 模板。模板会优先挂到当前选中的 UI 控件下；如果没有选中 UI，但场景里存在 Canvas，会自动挂到第一个 Canvas 下；如果场景里没有 Canvas，编辑器会自动创建一个 `UI Canvas`。

#### 7.5 Play / Stop

中间工具栏按钮用于进入或退出运行状态：

- 三角图标：进入 Play。
- 方块图标：停止 Play，回到编辑状态。

进入 Play 后编辑器会运行当前场景逻辑；停止后回到编辑场景。

### 8. UI 编辑

Wheatear 当前 UI 采用 `UICanvasComponent + UIWidgetComponent + 具体表现组件` 的组合。

#### 8.1 UI Canvas

`UI Canvas` 是 UI 的根画布。它通常带有：

- `UICanvasComponent`：记录参考分辨率、可见性等 Canvas 配置。
- `UIWidgetComponent`：让 Canvas 本身成为全屏 UI 区域，方便子控件挂载。

运行时底层仍保留对旧 UIWidget 场景的兼容，但正式页面统一要求放在 Canvas 下。Canvas 的价值是把 UI 根、参考分辨率和父子层级显式化，方便做多分辨率适配、复杂页面管理和专属 UI 编辑。

选中 Canvas 后，Inspector 的 `UI Canvas` 组件里会出现：

- `Edit Canvas`：打开专属 UI 编辑视窗，并把当前 Canvas 作为编辑目标。
- `Hide UI In Scene Viewport`：隐藏主 Viewport 中的 UI 渲染，方便改后面的场景物体。

#### 8.2 UI Widget

`UIWidgetComponent` 负责布局：

- `Visible`：是否可见。
- `Anchor`：锚点。
- `Position`：归一化位置。
- `Size`：归一化尺寸。
- `SortOrder`：绘制层级，数值越大越靠上。
- `Parent Tag`：父 UI 的实体名。

常用布局预设包括全屏、顶部栏、底部栏、左右侧栏和居中面板。可以先用预设快速摆位，再在 Viewport 或 Canvas Editor 里拖动微调。

#### 8.3 在主 Viewport 编辑 UI

打开 `View / UI Edit Outlines` 后：

- UI 控件会显示边框。
- 点击 UI 控件可以选中。
- 拖控件主体可以移动。
- 拖八个缩放点可以改变尺寸。
- 按住 `Ctrl` 拖动可以吸附到细网格。

主 Viewport 中的 UI 编辑适合快速对齐游戏画面里的 HUD、按钮和提示框。

#### 8.4 专属 UI Canvas Editor

打开方式：

- 选中 Canvas，在 Inspector 点击 `Edit Canvas`。
- 或从菜单 `View / UI Canvas Editor` 打开。

这个窗口只显示 UI 画布，不显示场景世界物体。适合调整菜单、背包、技能树、结算页、VN 对话框等复杂 UI。

操作方式：

- `Use Selected Canvas`：把当前选中的 Canvas 作为编辑目标；如果当前选中的是 Canvas 下的子控件，则会自动切换到它所属的 Canvas。
- 点击控件：选中 UI 实体。
- 拖控件主体：移动。
- 拖边角或边线 handle：缩放。
- 勾选 `Hide UI In Scene Viewport`：主 Viewport 暂时隐藏 UI，但 Canvas Editor 仍然可以编辑 UI。

#### 8.5 文本框缩放和字号

如果选中的 UI 实体同时有 `UIWidgetComponent` 和 `UITextComponent`，在 Viewport 或 UI Canvas Editor 里拖动缩放点改变文本框大小时，`UITextComponent.FontSize` 会跟随控件面积比例自动变大或变小。

这个缩放会和 UI 尺寸变化一起进入同一条撤销记录。若需要精确数值，仍然可以在 Inspector 的 `UI Text / Font Size` 字段手动输入。

#### 8.6 UI 组件用途

- `UICanvasComponent`：UI 根画布。
- `UIWidgetComponent`：所有 UI 控件的布局基础。
- `UIPanelComponent`：面板底图、颜色、裁剪子控件。
- `UIImageComponent`：图片显示。
- `UITextComponent`：文本显示。
- `UIButtonComponent`：按钮和点击函数名。
- `UIProgressBarComponent`：进度条。
- `UISliderComponent`：滑条和数值变化函数名。
- `UIPagerComponent`：已知页数的分页控制器，例如信件、图鉴、任务页、存档页。
- `UIPageItemComponent`：分页内容项，指定自己属于哪个 Pager，以及在哪一页显示。
- `UIPathComponent`：UI 曲线/路线绘制，可用于技能树装饰线、地图路线、任务路线和图鉴连线。
- `UICheckboxComponent`：复选框和数值变化函数名。
- `UIAnimatorComponent`：UI 动画状态。

`UIPanelComponent` 可以勾选 `Draggable` 让面板在运行时可拖动。`Constrain To Parent` 建议保持开启：如果面板挂在父控件下，就限制在父控件内；如果直接挂在 Canvas 下，就限制在画布内。`Handle Height` 控制可拖动区域高度，`0` 表示整个面板都可拖动。

`UISliderComponent` 适合连续滚动或数值调节；`UIPagerComponent` 适合总页数已知的内容切页。分页按钮可在 `UIButtonComponent.OnClickFunction` 中填写：

```text
ui:pager:@<PagerUUID>:next
ui:pager:@<PagerUUID>:prev
ui:pager:@<PagerUUID>:page:<number>
```

给内容控件添加 `UIPageItemComponent` 后，在对象槽里选择对应 Pager，并填写 `Page`，运行时只会在对应页显示。

### 9. Content Browser

`Content Browser` 用于浏览项目资源。

常用操作：

- 左上按钮返回、前进、上一级。
- 面包屑路径可快速跳转父目录。
- 右键文件可打开资源菜单。
- 右键空白处可新建文件夹或刷新。
- 拖 `.wt` 到 Viewport 打开场景。
- 拖 `.wtprefab` 到 Viewport 实例化 Prefab。
- 拖 `.wtuit` 到 Viewport 实例化 UI 模板。
- 某些 Inspector 字段支持从 Content Browser 拖入贴图、材质、音频或字体资源。

资源数据库按钮：

- `Rescan Assets`：重新扫描 `assets` 目录，更新中央 `asset_registry.yaml`。添加、删除、替换大量资源后使用。
- `Write Registry`：把当前 Inspector 中修改过的导入设置、标签和模板信息写回中央 Registry。
- `Generate UI Templates`：生成内置 `.wtuit` UI 模板描述，并刷新 Registry。

Wheatear 当前不再使用每个资源旁边的 `.wtmeta` 作为正式工作流。资源 UUID、导入设置和引用关系统一保存到 `assets/.wheatear/asset_registry.yaml`；打包时 `.wheatear`、`.wtuit` 和历史 `.wtmeta` 都不会进入运行包。

资源建议保存在 `WheatearEditor/assets` 下，并按功能划分目录，例如：

```text
assets/scenes
assets/fonts
assets/shaders
assets/vertical_slice
assets/prefabs
assets/materials
assets/audio
```

### 10. Animation Editor

`Animation Editor` 会跟随当前选中实体。

常用流程：

1. 选中带 `SpriteAnimatorComponent` 的实体。
2. 在动画编辑器中添加或选择 Clip。
3. 配置 `Loop`、`Set Default`、`Play On Start` 和 `Fire Events`。
4. 用 `Sprite Sheet Picker` 或 `Spritesheet / Atlas Generator` 从图集生成帧，或在 `Frames` 区域手动拖入贴图。
5. 使用时间轴预览动画。
6. 在 `Events` 轨道双击或点击 `+ Add Event` 添加动画事件。
7. 需要时增加属性轨道和关键帧，例如透明度、颜色、位置和缩放。

动画事件可以在运行时执行 `CommandBus` 命令，常见示例：

```text
anim:play:{entity}:idle
anim:play:Enemy_Bear:hurt
event:attack_hit
turn:skill:resolve_hit
```

事件命令支持 `{entity}`、`{clip}`、`{event}` 三个占位符。正式资源建议优先使用 spritesheet：一张贴图配多段 UV 帧，比每帧独立贴图更利于批处理和资源管理。

当前动画编辑器适合做 Sprite 序列帧、spritesheet 帧、简单属性动画、UI 动画和事件触发。复杂骨骼动画、动画状态机、Blend Tree 还没有做成完整商业级工具。

#### 10.1 Sprite Sheet Picker

`Sprite Sheet Picker` 是通用图集选择器，服务三类工作：

- 角色、敌人、特效：从横向连续帧或规则网格中生成 `AnimationClip` 序列帧。
- UI 图标：从一张 UI icon atlas 中选中某个格子，写入 `UIImageComponent.Texture + UVMin + UVMax`。
- 静态 Sprite：从 atlas 中选一个子图，写入 `SpriteRendererComponent.Texture + UVMin + UVMax`。

打开方式：

- 顶部菜单 `View / Sprite Sheet Picker`。
- 选中 `Sprite Renderer` 或 `UI Image` 组件后点击 `Open Sprite Sheet Picker`。
- 在 `Animation Editor / Spritesheet / Atlas Generator` 中点击 `Open Sprite Sheet Picker`。

基本操作：

1. 从 `Content Browser` 把图集拖到面板顶部的 drop 区。
2. 填写 `Columns / Rows`。如果是横向连续帧，通常 `Rows = 1`。
3. 默认 `Top-origin rows` 表示第 0 行是视觉上的最上面一行，符合 UI 图集和美术软件直觉；如果要兼容旧式底部 UV 起点，可以取消勾选。
4. 在大预览区点击一个格子，右侧会显示当前子图预览和 UV。
5. 静态图用 `Apply To SpriteRenderer` 或 `Apply To UI Image`。
6. 动画用 `Horizontal Strip / Row Major / Vertical Strip` 设置帧序列方向，再点击 `Replace Clip With Sequence` 或 `Append Sequence To Clip`。

建议约定：

- UI 图标图集命名为 `ui_icons_*.png`，按固定格子大小排布。
- 横向动作帧命名为 `character_action_sheet.png`，一行动作尽量保持同尺寸同中心点。
- 正式资源优先图集化；只有临时 Demo 或特殊独立大图才用单张 PNG。

### 11. VN 内容编辑

VN 场景实体通常带 `VisualNovelComponent`。

操作方式：

1. 在场景中选中带 `VisualNovelComponent` 的实体。
2. 在 Inspector 找到 `Visual Novel` 组件。
3. `Script Path` 指向 `.vn` 剧本文本。
4. 点击 `Open VN Script Editor`，或者从顶部菜单 `View / VN Script Editor` 打开独立窗口。
5. `Timeline` 页签按剧情顺序显示脚本行，可以新增台词、BGM、选项、角色登场、背景、标签、跳转和结束命令。
6. 选中某一行后，在右侧编辑区修改说话人、台词、表情、BGM 路径、BGM 显示名、选项文本和跳转目标。
7. `Characters / BGM` 页签用于集中检查人物声明和音乐切换点。
8. 点击 `Save` 写回 `.vn` 文件。
9. 点击 `Reload` 可放弃面板内修改并重新从磁盘读取。

VN 脚本音乐命令：

```text
@music assets/vertical_slice/audio/bgm/vn_school_morning.wav "晨路微光"
@bgm assets/vertical_slice/audio/bgm/vn_unease.wav "路口异兆"
@music none
```

运行时遇到音乐命令会切换循环 BGM，并在左上角显示一条短暂滑入/淡出的 BGM 名称提示。

注意：VN Script Editor 修改的是外部文本资源，不是场景内组件字段，所以它不走场景撤销栈。保存前请确认文本内容。

### 12. 横板战斗参数编辑

横板战斗关卡实体通常带 `SideCombatLevelComponent`。

操作方式：

1. 选中带 `SideCombatLevelComponent` 的实体。
2. 在 Inspector 找到 `Side Combat Level`。
3. 场景范围、地面高度、结算跳转等常用字段可以直接在组件上改。
4. `Tuning Path` 指向战斗调参 YAML。
5. 点击 `Open Side Combat Tuning Editor`，或者从顶部菜单 `View / Side Combat Tuning Editor` 打开独立窗口。
6. `Feel` 页签调最常用的手感：跳跃高度、下落速度、空中滞空、上挑高度、空中普攻抬升、断限追击。
7. `Rules` 页签调战斗规则：连击掉落、受击无敌、伤害、防御、Boss 保护槽、敌人 AI、拾取物、纵深移动、阴影和反馈音量。
8. `Attacks` 页签按招式 ID 调 hitbox、伤害、前摇、后摇、取消窗口、击飞、滞空、特效帧、音效、hit pause 和震屏。
9. `Skills` 页签管理技能显示名、输入、连招定位、绑定招式、解锁章节和核心技能标记。
10. `Progression` 页签管理不同章节/副本 profile：解锁技能、调试技能、Boss 保护槽 HUD、断限提示等系统可见性。
11. 点击 `Save` 写回 `side_combat_tuning.yaml`。
12. 如需直接修 YAML，可以展开 Inspector 里的 `Raw Side Combat Tuning YAML`，它是文本级兜底编辑器。

调参 YAML 是运行时读取的游戏数据，适合策划反复试手感。打包后如果该 YAML 被包含在资源包内，需要重新打包才会进入新的运行包。

注意：专用面板保存时会按结构化 YAML 重写文件，适合长期把该文件交给编辑器维护；如果要保留手写注释，先在文本兜底编辑器里确认再保存。

### 13. Prefab

保存 Prefab：

1. 在 Hierarchy 中右键实体。
2. 点击 `Save as Prefab`。
3. 文件会保存到 `assets/prefabs`，后缀为 `.wtprefab`。

使用 Prefab：

1. 在 `Content Browser` 找到 `.wtprefab`。
2. 拖到 Viewport。
3. 编辑器会在当前场景实例化一份。

### 14. 打包流程

#### 14.1 基本步骤

1. 打开入口场景，例如主菜单或竖切入口。
2. `Ctrl+S` 保存场景。
3. 点击 `File / Package Player`。
4. 等待 `Player Build Status` 显示成功。
5. 点击 `Open Build Folder` 打开输出目录。

#### 14.2 脚本版本

如果当前游戏确实使用 C# ScriptComponent，请选择：

```text
File / Package Player With C# Scripts
```

如果当前竖切主要使用引擎 C++ 模块、VN 数据和 YAML 调参，不需要 C# 脚本，可使用普通 `Package Player`。

#### 14.3 资源包

打包器会从入口场景开始收集引用资源，并生成自定义资源包：

```text
content.wtpack
```

这样不会把整个 `assets` 目录粗暴复制到包里。若某些资源是通过文本脚本、YAML 或运行时代码间接引用，需要确保它们能被场景、脚本文件或打包规则追踪到。

### 15. 推荐编辑工作流

#### 15.1 做一个普通 2D 场景

1. 进入 `2D Mode`。
2. `File / New` 新建场景。
3. 右键 Hierarchy 创建 Camera 和 Sprite。
4. 在 Viewport 中用 `W/E/R` 调整实体。
5. 在 Inspector 添加物理、动画、脚本或音频组件。
6. `Ctrl+S` 保存为 `.wt`。

#### 15.2 做一个 UI 页面

1. 右键 Hierarchy 创建 `UI / Canvas`。
2. 选中 Canvas，点击 Inspector 的 `Edit Canvas`。
3. 在 Hierarchy 右键创建 Panel、Text、Button、Slider 等。
4. 保持 Canvas 或目标父控件被选中，新控件会自动挂到它下面。
5. 在 UI Canvas Editor 里拖动、缩放、对齐。
6. 文本框需要同步字号时，直接拖缩放点，字号会跟着尺寸变化。
7. 保存场景。

#### 15.3 调整 VN

1. 打开 VN 场景。
2. 选中 VN 控制实体。
3. 在 `VN Script Editor` 修改文本。
4. 保存脚本。
5. 点击 Play 测试对话和跳转。

#### 15.4 调整横板战斗

1. 打开战斗场景。
2. 选中 `Side Combat Level` 实体。
3. 点击 `Open Side Combat Tuning Editor`，或从 `View / Side Combat Tuning Editor` 打开专用调参窗口。
4. 在 `Feel` 页调跳跃、重力、滞空、上挑、空中普攻和断限追击。
5. 在 `Attacks` 页调每一招的 hitbox、伤害、前后摇、取消窗口、击飞、hit stun、音效、hit pause 和震屏。
6. 在 `Rules / Skills / Progression` 页调战斗规则、技能显示、章节解锁和关卡 profile。
7. 点击 `Save` 写回 `side_combat_tuning.yaml`。
8. Play 测试；找到较好手感后再打包。

### 16. 当前已知边界

- UI 父子关系目前基于 `Parent Tag`，已经支持布局、可见性、裁剪和 Hierarchy 缩进显示，但还不是完整的通用实体 Transform 父子系统。
- UI Canvas Editor 已支持单选、拖动、缩放、隐藏主 Viewport UI；多选、框选、对齐、等距分布、拖拽改父还没有做。
- 撤销/复原覆盖常用场景编辑，但 VN Script Editor 和 Side Combat YAML Editor 属于外部文本文件编辑，不纳入场景撤销栈。
- Inspector 字段修改会进入撤销栈；极少数复杂控件可能需要后续继续做更细的合并规则。
- 文本框拖拽缩放会按面积比例调整字号，但不等同于完整自动排版系统。长文本换行、溢出裁剪和富文本仍需继续打磨。
- 打包器会追踪场景和常见资源引用；间接字符串引用资源要注意打包规则。

### 17. 故障排查

#### 17.1 编辑器布局乱了

关闭编辑器，删除：

```text
%LOCALAPPDATA%/Wheatear/Wheatear Editor/imgui.ini
```

重新打开编辑器。

#### 17.2 场景打不开

确认文件后缀是 `.wt`，并且路径在项目资源目录下。若是手工编辑过 YAML，优先检查缩进和冒号。

#### 17.3 UI 子控件不显示

检查：

- 子控件 `Visible` 是否开启。
- 父控件 `Visible` 是否开启。
- `Parent Tag` 是否和父实体名字完全一致。
- 父控件是否裁剪了子控件。
- `SortOrder` 是否被其他控件遮挡。

#### 17.4 文本太大或太小

如果拖动文本框后字号不合适，在 Inspector 的 `UI Text / Font Size` 手动输入数值即可。再次拖动缩放点时，字号会继续按新的尺寸比例变化。

#### 17.5 打包后资源缺失

确认资源是否被场景、Prefab、VN 脚本、YAML 或打包规则引用。若资源只是临时放在目录里但没有任何引用，打包器可能不会收集它。

### 18. Project Health / 项目体检

打开方式：

```text
View -> Project Health
```

常用页签：

- `Summary`：查看资源、场景、脚本、工程源文件同步等总体状态。
- `Source Sync`：检查源码目录和 Visual Studio 工程文件是否一致。

`Source Sync` 重点看两类问题：

- `Missing From Project` 表示磁盘上有源码但 `.vcxproj` 没登记，通常会导致 VS 或 CI 构建漏编译。
- `Stale Project Entry` 表示 `.vcxproj` 里有旧路径但磁盘文件不存在，通常来自重命名或删除后没清工程文件。

同一个检查也可以在命令行执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Check-ProjectSources.ps1
```

建议每次新增 C++ 服务、编辑器面板、玩法模块后都跑一次。

### 19. WAO Action 数据

WAO action 数据位于：

```text
WheatearEditor/assets/gameplay/actions/
```

当前四种玩法都有对应 action 表：

- 弹幕假玩法：`00_arcade_actions.yaml`
- 横板格斗：`10_side_combat_actions.yaml`
- 回合制战斗：`20_turn_combat_actions.yaml`
- 战旗战斗：`30_tactical_combat_actions.yaml`

这些文件会在运行时加载，也会被打包器收集到玩家包里。以后新增技能时，优先在对应玩法的 action YAML 里补图标、音效、特效、标签和效果预览；真正决定手感的玩法专属参数仍放在对应 tuning 或技能服务里。
### 20. 近期生产力更新

#### 20.1 WAO Action Debugger

打开方式：

```text
View -> WAO Action Debugger
```

左侧 action 列表可以勾选 `Group by module`，按弹幕假玩法、横板战斗、回合制、战棋等模块分组。选中 action 后，在 `Recipe` 页可以查看对应 YAML、side combat 调参表、图标、音效、特效资源路径。

每个资源路径旁边有：

- `Open Folder`：打开资源所在目录。
- `Copy Path`：复制绝对路径，方便在资源管理器或外部工具里定位。
- `Missing`：资源不存在时显示，优先修这个。

#### 20.2 Project Health Scene Links

打开方式：

```text
View -> Project Health -> Scene Links
```

该页会列出从入口场景开始追踪到的所有 `scene:` / `newgame:` / `loadgame:` 跳转。若某个跳转目标不存在，会在上方显示缺失列表。准备打包前建议先点一次 `Refresh`。

#### 20.3 打包前门禁

`Package Player` 现在会在写入资源包前执行依赖 preflight。如果发现缺失资源或缺失场景跳转，会停止打包，并在输出目录生成：

```text
Builds/Windows/Player/package_preflight_report.txt
```

正常打包成功时，输出目录仍会生成：

```text
Builds/Windows/Player/package_report.txt
```

报告中会包含 packed assets、missing references、scene transitions 和 missing scene transitions。

#### 20.4 设置页运行时偏好

据点设置页里的全屏按钮已经接到窗口系统，会立即切换全屏/窗口模式，并随存档保存。主音量、BGM、音效继续走项目统一的非线性音量曲线；默认音量已经调低到更适合试玩的区间。屏幕震动开关继续控制横板战斗 hit feedback。
### 21. 用户设置、输入映射与 WAO 编辑

#### 21.1 用户设置

运行时偏好已经从进度存档里拆出来，统一保存到：

```text
assets/saves/user_settings.wtsettings
```

它负责文字速度、主音量、BGM 音量、音效音量、全屏、屏幕震动和按键映射。进度存档只保存章节、材料、装备、技能、好感度等游戏进度，不再保存这些用户偏好。

#### 21.2 输入映射

常用输入通过 `InputBindingService` 读取，例如：

- `move.left` / `move.right` / `move.up` / `move.down`
- `game.pause`
- `side.jump` / `side.basic` / `side.magic` / `side.support` / `side.break_limit`
- `arcade.attack` / `arcade.weapon1` / `arcade.weapon2` / `arcade.weapon3`
- `vn.advance` / `vn.auto` / `vn.history` / `vn.save` / `vn.load`

当前横板格斗、类元气假玩法和 VN 常用快捷键已经接入这层服务。后续做改键面板时，编辑器只需要改 `UserSettings.KeyBindings`，玩法系统不需要知道具体键盘码。

#### 21.3 WAO Action Debugger 编辑模式

打开方式：

```text
View -> WAO Action Debugger
```

选择一个 action 后，在 `Recipe` 页点击 `Edit Recipe`，可以直接编辑并保存这些常用字段：

- 名字、描述、图标路径、动画 ID、音效路径、VFX 路径
- 冷却、持续时间、前摇、命中时间、后摇、取消窗口、移动倍率
- tags、signals、resourceCost

点击 `Save YAML` 后会写回 `WheatearEditor/assets/gameplay/actions/` 下对应 YAML，并立即刷新当前运行中的 `ActionDatabase`。效果列表目前仍是查看和调试用；后续如果需要更深的策划工具，再升级为效果行级编辑器。

## 编辑器模块内容编辑流程

更新时间：2026-07-29

本文记录 WheatearEditor 当前针对游戏模块内容的编辑方式，目标是让策划和程序都能直接在编辑器里微调竖切内容，而不是只能靠代码生成场景文件。

### VN 模块

- 在场景中选中带有 `VisualNovelComponent` 的实体。
- 右侧 `Properties` 面板会显示 `Visual Novel` 组件。
- `Script Path` 用来指定 `.vn` 剧本文本资源。
- `VN Script Editor` 会直接读取这个脚本文件，可以从顶部 `View / VN Script Editor` 打开，也可以在组件面板点击 `Open VN Script Editor` 打开当前脚本。
- `Timeline` 页签用于按行管理剧情流程：台词、角色登场、背景、BGM、选择项、标签、跳转、结束命令都能在右侧编辑区改。
- `Characters / BGM` 页签用于集中检查人物命令和音乐切换命令，适合快速维护角色、表情、BGM 插入点。
- 修改对话文本、人物、表情、BGM、跳转命令、选择项后，点击 `Save` 会写回脚本文件。
- 点击 `Reload` 可以放弃当前面板文本，重新从磁盘读取。

VN 脚本支持 `@music <path> "<display name>"` 或 `@bgm <path> "<display name>"`，运行时会切换循环 BGM，并在左上角弹出音乐名提示。当前实现是时间线表格式编辑，适合快速改台词和流程；后续可以继续升级为节点式 VN 编辑器。

### 横板战斗模块

- 在场景中选中带有 `SideCombatLevelComponent` 的实体。
- 右侧 `Properties` 面板会显示 `Side Combat Level` 组件。
- 常用场景参数，例如场地范围、地面高度、结算跳转命令，可以直接在组件字段里改。
- `Tuning Path` 用来指定战斗调参 YAML。
- 点击 `Open Side Combat Tuning Editor`，或者从顶部 `View / Side Combat Tuning Editor` 打开独立调参窗口。
- `Feel` 页签用于高频手感参数：移动、跳跃、重力、滞空、上挑、空中普攻、空中追击、断限追击。
- `Rules` 页签用于战斗规则：连击掉落、受击无敌、伤害公式、音量反馈、Boss 保护槽、敌人 AI、拾取物、纵深移动和阴影。
- `Attacks` 页签用于逐个招式编辑 hitbox、伤害、前摇、后摇、取消窗口、击飞、滞空、保护槽增长、特效帧和音效。
- `Skills` 和 `Progression` 页签用于维护技能显示、输入、招式绑定、章节解锁和不同关卡 profile 的可见系统。
- 修改后点击 `Save` 会写回同一个 `side_combat_tuning.yaml`。
- 需要精修 YAML 时，可以展开 Inspector 里的 `Raw Side Combat Tuning YAML` 作为文本级兜底。

当前实现是“专用调参面板 + YAML 兜底编辑”。YAML 仍是运行时唯一数据源，避免面板数据和运行数据分裂。

### 事件脚本模块

- 在场景中创建一个流程控制实体，例如 `FlowController`。
- 右侧 `Properties` 点击 `Add Component / Scripting & Audio / Event Script`。
- `Script Path` 指向 `.wts` 文件，例如 `assets/events/vertical_slice_flow_sample.wts`。
- `Start Event` 填默认启动事件名，通常是 `on_start`。
- `Run On Start` 表示场景运行时自动执行该事件；如果只想由按钮或剧情触发，可以取消勾选。
- `Run Once` 表示同一组件生命周期内只执行一次，适合一次性剧情事件。
- 组件下方内置 `.wts` 文本编辑器，可以直接修改并保存脚本。
- UI 按钮可以通过 `event:open_skill_tree` 触发当前场景的流程事件；需要精确指定实体时使用 `event:@<UUID>:open_skill_tree`。

`.wts` 只负责流程编排。大量战斗数值仍写在 `side_combat_tuning.yaml`，VN 台词仍写在 `.vn`，场景切换通过引擎 `SceneTransitionService` 请求，不直接依赖 `WheatearSandbox`。

### 层级选中同步

- 从 Scene Viewport 点选实体后，左侧 `Scene Hierarchy` 会自动滚动到对应实体。
- 对应行保持 ImGui 选中高亮。
- 如果当前搜索条件或 `UI` 过滤导致选中实体不可见，Hierarchy 会提示该实体被过滤隐藏，并提供清空过滤按钮。

### 直接打开编辑器

新增脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Build-WheatearEditor.ps1
```

脚本会构建 `WheatearEditor`，并复制输出到：

```text
Builds\Windows\Editor\WheatearEditor.exe
```

之后可以直接打开这个 exe，不需要每次从 Visual Studio 启动。
