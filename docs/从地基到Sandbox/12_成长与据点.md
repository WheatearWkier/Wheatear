# Part 12 · 成长与据点：全局状态、技能树与存档

> 目标：理解竖切的成长循环如何落地——跨场景全局状态（GameProgress）、
> 据点各页面的服务化、存档系统的分层。

## 12.1 全局状态：GameProgress

玩法循环里最大的需求是**跨场景共享进度**：VN 里选的选项影响
战斗数值，战斗掉的材料在据点里强化装备，装备又带回战斗。
实现是单例状态 `Modules/Progression/GameProgress.h`：

```cpp
struct State
{
    int CurrentChapter = 2;
    std::string Objective;               // 当前目标文本（HUD 显示）
    std::string CurrentScenePath;        // 当前场景（切场景用）
    std::string PreviousScenePath;       // 上一个场景（结算回退用）

    int PlayerLevel = 1;
    int Experience = 0;
    int ExperienceToNext = 0;
    int MagicSwordLevel = 1;
    int Gold = 0;
    PlayerAttributes Attributes;         // 攻击/防御/生命（战斗读它）

    std::unordered_map<std::string, int> Materials;          // 掉落材料
    std::unordered_set<std::string> CompletedDungeons;       // 通关副本
    std::unordered_set<std::string> UnlockedDungeons;        // 解锁副本
    std::unordered_set<std::string> UnlockedSkills;          // 已解锁技能
    std::unordered_set<std::string> OwnedEquipment;          // 拥有装备
    std::unordered_map<std::string, std::string> EquippedItemsBySlot;  // 穿戴
    std::unordered_set<std::string> StoryFlags;              // 剧情标记（Part 9）
    std::vector<RelationshipRecord> Relationships;           // 角色好感（记录数组）
    std::string ActiveSupportCharacterId;                    // 当前支援角色
    std::string SelectedSkillNodeId;                         // 技能树选中节点
    std::string ActiveSideCombatDungeonId;                   // 当前战斗副本
    std::string LastDungeonResult;                           // 上一场副本结果（结算分流）
    // ...
};

WHEATEAR_API State& GetState();   // 全局单例
```

**设计要点**：

1. **全局单例而非场景组件**：进度不属于任何场景——场景切换时
   它必须存活。`GetState()` 是运行器/编辑器进程级的。
2. **值类型 + 集合**：全是 POD/集合，序列化天然简单
   （存档 = 把 State 写成 `key=value` 文本，见 12.4）。
3. **所有模块共享**：VN 读 `StoryFlags`（选项门控，Part 9）、
   SideCombat 结算写 `Materials/Experience`、据点页面读写装备与
   好感——**一个状态，五个玩法**。

## 12.2 据点：页面服务化

据点场景（`VerticalSliceHub.wt` + 各子场景）的每个页面
（技能树/装备/关系/结算）对应一个服务：

```
Progression/
├── ProgressionContent.cpp          内容定义（技能/装备/词条数据）
├── ProgressionSkillTreePageService 技能树页面逻辑
├── ProgressionEquipmentPageService 装备页面（槽位/穿戴/强化）
├── ProgressionResultPageService    战斗结算页面
└── ... 关系页面等
```

页面服务模式：**场景实体是 UI（UIText/UIImage/UIButton），
服务写内容**——每帧把 State 渲染进实体
（技能名/等级/花费），按钮点击走 CommandBus 命令
（`prog:unlock_skill` → 服务校验材料 → 更新 State → 刷新 UI）。
与 Part 10 的 HUD 同款"数据驱动渲染"。

## 12.3 成长循环（竖切链路）

```
战斗胜利（SideCombat）→ 结算页面（掉落材料/经验/评价）
→ 据点：技能树解锁新技能（材料消耗）→ 装备强化（材料消耗）
→ 好感（VN 选项影响）→ 战斗数值加成（Attributes 来自装备+技能+好感）
→ 继续剧情（Objective/章节推进）→ 存读档
```

材料经济：`Materials` 是唯一货币池（掉落写、强化扣），
技能/装备/好感都读它——**一个数据源，多条消费线**，
不会出现"三个系统各存一份钱"的同步 bug。

## 12.4 存档系统：状态快照

`GameProgress` 提供分层存档 API：

```cpp
GetProgressSavePath(slot);       // 进度存档路径（assets/saves/progression_slot{N}.wtsave）
GetGameRuntimeSavePath(slot);    // VN 运行时存档路径（assets/saves/slot{N}.vnstate）
ClearGameRuntimeSaveSlot(slot);  // 清档
IsSaveSlotOccupied(slot);        // 槽位占用检查（UI 用）
```

- **存档内容 = State 快照 + 当前场景路径 + VN 播放位置**
  （Part 9 讲过 VN 的进度 = 剧本 + 行号）。进度存档是 `key=value`
  文本格式（`schema=wheatear.progress.v3`），VN 运行时存档是 `.vnstate`。
- 槽位信息（`SaveSlotInfo`：章节/等级/金币/目标文本）单独存，
  存读档 UI（`VerticalSliceSaveLoad.wt`）列表显示不用读全量。
- `SaveVersion` 字段预留兼容——旧档升级是存档系统的必修课。
