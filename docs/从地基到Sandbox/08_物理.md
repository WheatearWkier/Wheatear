# Part 8 · 物理：Box2D 集成与动画驱动碰撞

> 目标：理解 Box2D 如何与 ECS 集成（会话式世界、fixture 生命周期），
> 以及"碰撞盒跟随动画"这一引擎特色功能的两层实现
> （数据驱动 + fixture 重建）。结尾用战斗角色碰撞实例收束。

## 8.1 集成模式：会话式世界，不是常驻世界

`Systems/PhysicsSystem.cpp`：

```cpp
void PhysicsSystem::OnRuntimeStart(Scene* scene)
{
    m_PhysicsWorld = std::make_unique<b2World>(b2Vec2{ 0.0f, -9.8f });  // 重力
    m_ContactListener = std::make_unique<ContactListener>(scene);
    m_PhysicsWorld->SetContactListener(m_ContactListener.get());

    for (auto e : scene->GetRegistry().view<Rigidbody2DComponent>())
        InitEntityPhysics(scene, { e, scene });   // 为每个刚体建 body
}

void PhysicsSystem::OnRuntimeStop(Scene* scene)
{
    m_PhysicsWorld.reset();       // RAII：离开 Play 世界销毁
    m_ContactListener.reset();
}
```

关键设计：**b2World 只在运行时存在**（`OnRuntimeStart` 创建、
`OnRuntimeStop` 销毁）。编辑态不跑物理——场景数据（组件）是权威，
Box2D 世界只是运行时的"模拟副本"。这带来：

1. **编辑/运行时切换零清理成本**：离开 Play 自动销毁世界。
2. **场景序列化只存组件**：`Rigidbody2DComponent` 的
   `RuntimeBody` 指针不参与序列化（运行时态字段，模板序列化器
   只写物理参数：Type/GravityScale/FixedRotation/Size/Offset...）。
3. **编辑器显示碰撞盒**：读组件数据画矩形（编辑系统集），
   与运行时 fixture 无关。

## 8.2 实体 ↔ Box2D 的映射

`InitEntityPhysics`：

```cpp
b2BodyDef bodyDef;
bodyDef.type = RigidbodyTypeToBox2D(rb2d.Type);       // Static/Dynamic/Kinematic
bodyDef.position = { tc.Translation.x, tc.Translation.y };
bodyDef.angle = tc.Rotation.z;
b2Body* body = m_PhysicsWorld->CreateBody(&bodyDef);
body->GetUserData().pointer = (uint64_t)entity.GetUUID();   // 实体回指
rb2d.RuntimeBody = body;

if (entity.HasComponent<BoxCollider2DComponent>())
{
    auto& bc = entity.GetComponent<BoxCollider2DComponent>();
    b2PolygonShape shape;
    shape.SetAsBox(bc.Size.x * tc.Scale.x, bc.Size.y * tc.Scale.y,
                   { bc.Offset.x, bc.Offset.y }, 0.0f);
    bc.RuntimeFixture = body->CreateFixture(...);     // fixture 指针存回组件
}
```

- **Transform 组件是权威**：创建 body 时从组件读位置。
- **UserData 存 UUID**：碰撞回调（`ContactListener`）拿到 body →
  UUID → 找到实体（`scene->GetEntityByUUID`）。
- **RuntimeBody/RuntimeFixture 指针**：运行时态字段，不序列化。

每帧同步（`OnUpdateRuntime`）：

```cpp
m_PhysicsWorld->Step(ts, 6, 2);        // 物理步进（6 速度迭代/2 位置迭代）

for (auto e : view<TransformComponent, Rigidbody2DComponent>())
{
    const auto& pos = body->GetPosition();
    tc.Translation.x = pos.x;          // body → Transform 写回
    tc.Translation.y = pos.y;
    tc.Rotation.z = body->GetAngle();
}
```

**单向同步**：身体位置 → Transform。如果玩法代码直接改 Transform
（传送/脚本），需要额外机制（`SetBodyTransform` 之类）——单机
2D 里最常见的是物理驱动，所以默认单向。

## 8.3 动画驱动碰撞：引擎特色功能

这是本项目区别于教科书 Box2D 集成的点。需求：
**动画帧内容尺寸变化（站立→躺下）时，碰撞盒跟着变**。

### 8.3.1 数据层：格子碰撞框 → 组件

`SpriteSheetSystem::ApplyColliderToEntity`（Part 6 的 ResolveCell
输出碰撞框）：

```cpp
void SpriteSheetSystem::ApplyColliderToEntity(entt::registry& registry,
    entt::entity entity, const SpriteSheetAsset::ResolvedCell& resolved)
{
    if (!resolved.HasCollider) return;
    if (!registry.all_of<BoxCollider2DComponent>(entity)) return;
    auto& box = registry.get<BoxCollider2DComponent>(entity);
    if (!box.FollowAnimation) return;              // 开关：默认关
    const float ppu = ...PixelsPerUnit;            // 像素→世界单位
    if (ppu <= 0.0f) return;

    box.Size = { resolved.ColliderWidth / ppu, resolved.ColliderHeight / ppu };
    // 碰撞框中心相对内容框中心的偏移（世界 Y 向上，内容 Y 向下）
    box.Offset = { dx / ppu, -dy / ppu };
}
```

- **开关**：`BoxCollider2DComponent.FollowAnimation`（默认 false）——
  只有明确需要的实体才被驱动，粒子/装饰不受影响。
- **需要 PPU > 0**：像素 → 世界单位的换算基准（Part 6）。
- 谁调用它？SpriteSheetSystem（静态 sheet 精灵）和
  AnimationSystem（动画帧，`ApplyFrameToSprite` 内）——两条路径
  都经过，所以静态精灵与动画精灵行为一致。

### 8.3.2 物理层：组件变化 → fixture 重建

Box2D 的 fixture 在创建时**拷贝 shape**，之后改组件数据 fixture
不会变。`PhysicsSystem::SyncAnimationDrivenColliders` 每帧比对：

```cpp
void PhysicsSystem::SyncAnimationDrivenColliders(Scene* scene)
{
    auto view = registry.view<Rigidbody2DComponent, BoxCollider2DComponent, TransformComponent>();
    for (auto e : view)
    {
        auto& bc = view.get<BoxCollider2DComponent>(e);
        if (!bc.FollowAnimation) continue;          // 只处理被动画驱动的

        const b2Vec2 desiredHalf(bc.Size.x * tc.Scale.x, bc.Size.y * tc.Scale.y);
        const b2Vec2 desiredCenter(bc.Offset.x, bc.Offset.y);

        b2Fixture* fixture = (b2Fixture*)bc.RuntimeFixture;
        if (fixture && fixture->GetType() == b2Shape::e_polygon)
        {
            const b2PolygonShape* shape = (b2PolygonShape*)fixture->GetShape();
            // 与当前 shape 比对：没变就不重建（避免每帧销毁/创建）
            if (shape->m_centroid == desiredCenter && 顶点一致)
                continue;
            body->DestroyFixture(fixture);
        }
        // 重建 fixture（组件数据是权威）
        b2PolygonShape shape;
        shape.SetAsBox(desiredHalf.x, desiredHalf.y, desiredCenter, 0.0f);
        bc.RuntimeFixture = body->CreateFixture(&fd);
    }
}
```

**"变了才重建"**：帧间碰撞框没变 → 零开销；
变了（动画切到不同形状的帧）→ 销毁旧 fixture 重建。
死亡动画从站立切到躺下，碰撞盒从高瘦变矮宽——"人躺下了，
碰撞盒还竖着"的穿模问题被彻底解决。

## 8.4 碰撞回调：ContactListener

`Physics/ContactListener.h` 继承 `b2ContactListener`，在
`BeginContact` 里用 UserData 的 UUID 找实体 → 触发实体上的
碰撞相关组件（战斗的 `SideCombatantComponent` 受击判定等，
Part 10 详讲）。**物理只报告"谁和谁碰了"，规则归玩法**。

## 8.5 实例：战斗角色碰撞

主角实体组件（`SideCombatBeastPath.wt`）：

```yaml
Rigidbody2DComponent:   { Type: Dynamic, GravityScale: 1 }
BoxCollider2DComponent: { Offset: [0, -0.2], Size: [0.66, 1.2],
                          FollowAnimation: true }
SpriteRendererComponent:{ Texture: protag_idle_sheet.png,
                          SpriteSheet: protag_idle_sheet.wtsheet,
                          CellIndex: 0, PixelsPerUnit: 400 }
```

- 按空格 → 动作层 `side.jump` → 战斗系统给速度 → Box2D 步进 →
  body 位置写回 Transform → 精灵跟随。
- 播放攻击动画 → 帧的碰撞框（在 `.wtsheet` 里配好）→
  `ApplyColliderToEntity` 更新组件 → `SyncAnimationDrivenColliders`
  重建 fixture → 攻击判定与动画形状同步。
- 掉进战斗区域边界 → ContactListener → 关卡逻辑。

> 面试可讲：物理世界是"运行时会话"而非常驻（编辑态零成本）；
> 组件是权威、fixture 是副本（单向同步）；动画驱动碰撞 = 
> 数据层（ResolveCell→组件）+ 物理层（比对重建）两层解耦，
> "变了才重建"避免每帧开销。
