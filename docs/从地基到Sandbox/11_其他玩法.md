# Part 11 · 其他玩法：回合制、战棋与弹幕的复用模式

> 目标：理解四个玩法模块（SideCombat / TurnCombat / TacticalCombat /
> ArcadeCombat）如何共享同一套引擎架构——系统 + 服务 + 数据表 +
> 命令管道——而各自只实现"自己的规则"。

## 11.1 模块的通用骨架

每个玩法模块都是同一套模板：

```
Modules/<X>Combat/
├── <X>CombatSystem.h/.cpp       系统：每帧调度（薄壳）
├── <X>CombatComponents.h        模块组件（挂在场景实体上）
├── <X>CombatFlowService         流程状态机
├── <X>CombatCommandService      命令处理（turn:xxx / side:xxx）
├── <X>CombatActionService       动作/技能执行
├── <X>CombatVisualService       动画/特效桥接（Part 6 的运行时帧生成）
└── <X>CombatTuningService       数据表加载（500ms 热重载）
```

共享底座（`Modules/GameplayModuleRuntime.h`）：

- **命令管道**：`RuntimeRequestedCommand`（组件字段）→
  `DrainRuntimeCommandsFromComponents` 每帧收集 → CommandBus。
  模块之间通过命令通信，不直接互调（解耦）。
- **动作层**：`GameplayModuleRuntime::UpdateActionHotReload`
  500ms 轮询数据表/事件脚本热重载（Part 4 降频表）。
- **ActionDatabase**：WAO 配方库（Part 10）——所有模块共享。

## 11.2 回合制：相位状态机

`TurnCombatComponents.h` 的相位机是回合制的骨架：

```cpp
enum class TurnCombatPhase
{
    Intro = 0,        // 开场演出
    AwaitCommand,     // 等待玩家选择指令
    AwaitTarget,      // 等待选择目标
    Acting,           // 演出/结算中
    Victory,          // 胜利
    Defeat            // 失败
};
```

流程由命令驱动（`TurnCombatCommandService`）：

```
玩家点技能按钮 → CommandBus "turn:skill:player:arc_slash"
  → AwaitCommand → AwaitTarget（选目标）
  → 确认 → Acting：播放技能演出 Clip（动画事件在 hit 帧触发结算）
  → turn:skill:resolve_hit → 伤害结算（EffectLedger）
  → 敌人回合 → 回到 AwaitCommand / Victory / Defeat
```

关键设计：**相位存在组件里**（`level.RuntimePhase`），
不是系统私有状态——序列化、调试、HUD 显示都能读。
演出动画与结算解耦：`Acting` 阶段动画事件（Part 6）
发 `turn:skill:resolve_hit`，结算服务消费——**表现与规则
通过命令总线同步**，和 SideCombat 的 `side.action.hit` 同款模式。

## 11.3 战棋：同一套底座，网格规则

`TacticalCombatSystem` 复用系统+服务+命令模式，差异只在规则域：
格子寻路、行动点数、范围攻击。它的动作也走 `ActionIntent`（WAO），
技能效果（伤害/状态/范围）是 Recipe 数据——**战棋与横板共享
效果结算代码**，只是"意图怎么产生"不同。

## 11.4 弹幕：ArcadeCombat

`ArcadeCombatSystem` 是第三个实例：移动/射击/弹幕生成。
它验证的是"**玩法定制速度**"：新玩法 = 新组件 + 新服务 +
新数据表，旧底座（渲染/输入/动画/命令/WAO）零改动。

## 11.5 复用模式总结（面试重点）

| 层 | 复用内容 | 各模块差异 |
| --- | --- | --- |
| 引擎 | 渲染/ECS/资产/输入/物理/动画 | 无（全部共用） |
| 命令管道 | RuntimeRequestedCommand → CommandBus | 命令前缀（side:/turn:/tactic:） |
| WAO | Recipe/Effect/Ledger/Signal | 意图来源与消费 |
| 系统+服务 | 薄系统 + 服务集模式 | 各自规则域 |
| 数据表 | YAML + TuningService + 热重载 | 表内容 |

面试话术："引擎提供的是**可组合的底座**（命令、动作、数据表、
资产、输入统一），玩法模块是底座上的**规则插件**——新增玩法
不需要碰引擎。" 这就是竖切里五个玩法能共存、且每个都能
独立调参的结构原因。
