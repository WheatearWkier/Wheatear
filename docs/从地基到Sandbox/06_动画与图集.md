# Part 6 · 动画与图集：AnimationClip、分割器与 Sheet 工作流

> 目标：理解动画系统的三层（Clip 数据 / 播放系统 / 编辑器生产），
> 以及 `.wtsheet` 引用式资产如何贯穿精灵、动画、碰撞三层。
> 结尾用主角 `idle` 动画从图集到播放的完整链路收束。

## 6.1 动画数据：AnimationClip 三件套

`Animation/AnimationClip.h` 定义动画数据模型：

```cpp
struct AnimationFrame
{
    Ref<Texture2D> Texture;         // 帧纹理（多帧共用一个图集）
    glm::vec2 TexCoordMin, TexCoordMax;  // 帧在纹理中的 UV
    float     Duration = 0.1f;      // 帧时长（秒）

    // 可选图集引用：非空时播放期经共享缓存解析（热更新/裁切/碰撞）
    std::string SpriteSheet;        // .wtsheet 路径
    int         CellIndex = -1;     // 规则格子号
};

class AnimationClip
{
    std::vector<AnimationFrame> m_Frames;                 // 序列帧
    std::vector<Ref<PropertyTrackBase>> m_PropertyTracks; // 属性轨道（颜色/位置/缩放）
    std::vector<AnimationEvent> m_Events;                 // 事件轨道
    bool m_Looping; std::string m_Name;
    // 注意：没有"默认 Clip"字段——默认播放哪个 Clip 由
    // SpriteAnimatorComponent::DefaultClipName 决定
};
```

- **Frames**：精灵序列帧（Part 2 的 UV 体系直接服务它）。
- **PropertyTracks**：属性动画——`AnimatedProperty` 枚举
  （SpriteColor / PositionX / ScaleX...），每个轨道是一串
  (Time, Value, 插值模式) 关键帧。`GetTotalDuration()` 综合
  帧时长 + 轨道时长 + 事件时间，保证纯事件/纯属性动画也有正确时长。
- **Events**：动画事件——在指定时间触发 `Command`（Part 1 的
  CommandBus 链路），支持 `{entity}/{clip}/{event}` 占位符。

## 6.2 播放系统：AnimationSystem 每帧做什么

`Systems/AnimationSystem.cpp` 的核心（双系统集行为，Part 3 讲过）：

```cpp
void AnimationSystem::OnUpdateEditor(Scene* scene, Timestep ts)
{
    if (!m_EditorPreviewActive)
        SyncEditorPreviewFrame(scene);   // 编辑态：只同步第一帧做预览
}
void AnimationSystem::OnUpdateRuntime(Scene* scene, Timestep ts)
{
    UpdateAnimations(scene, ts);         // 运行态：完整播放
}
```

`UpdateAnimations` 每帧：

1. **找当前帧**：按 `ElapsedTime` 在帧序列里定位
   （`acc += frames[i].Duration; if (t < acc) frameIdx = i`）。
2. **应用帧到精灵**（`ApplyFrameToSprite`）：

```cpp
if (!frame.SpriteSheet.empty() && frame.CellIndex >= 0)
{
    SpriteSheetAsset::ResolvedCell resolved;
    if (SpriteSheetAsset::ResolveCell(frame.SpriteSheet, frame.CellIndex, resolved))
    {
        texture = resolved.Texture;      // 共享缓存解析（250ms 热重载闸）
        uvMin = resolved.UVMin;
        uvMax = resolved.UVMax;
        SpriteSheetSystem::ApplyColliderToEntity(entity, resolved);  // 碰撞跟随
        return;
    }
}
texture = frame.Texture;                 // 兜底：内嵌烘焙 UV
```

3. **触发事件**：`FireAnimationEventsInRange(prev, now)` 在跨过
   事件时间的帧触发命令（含循环回绕处理）。
4. **应用属性轨道**：动画播放时按 `ElapsedTime` 对每条轨道调用
   `SampleValue(...)` 采样关键帧值，再写入组件（颜色/位置/缩放）——
   轨道与实体之间是轻量数据流，没有逐 clip 的绑定缓存，clip 切换零清理。

## 6.3 图集资产：.wtsheet 的三层能力

`.wtsheet`（YAML）是图集定义资产，三个渐进能力：

```yaml
texture: assets/vertical_slice/side_combat/sheets/runtime_characters/protag_idle_sheet.png
columns: 8        # ① 规则网格
rows: 1
trims:            # ② 逐格内容裁切（可选）
  - {left: 24, top: 32, width: 464, height: 448}
rects:            # ③ 命名矩形（不规则图集，可选）
  - {name: 'SC_SkillIcon_J', left: 289, top: 1010, width: 189, height: 184}
```

| 能力 | 解决什么 | 运行时 |
| --- | --- | --- |
| 规则网格 + CellIndex | 网格图集的基础引用 | `ResolveCell(sheet, index)` |
| 逐格 trim | 内容不居中/留白/帧间跳动 | 按内容框取 UV（自动对齐） |
| 命名矩形 SubRect | 不规则 HUD 图集 | `ResolveCell(sheet, name)` |
| 每格碰撞框 | 碰撞跟随动画 | `ApplyColliderToEntity` |

`ResolveCell` 输出 `ResolvedCell`（UV + 内容像素框 + 碰撞框），
**一条解析路径服务所有消费者**：SpriteSheetSystem（静态精灵）、
AnimationSystem（动画帧）、ContentBrowser（条带缩略图）、
缩略图渲染、视口拖放创建。

### PPU 真实尺寸

`SpriteRendererComponent.PixelsPerUnit > 0` 时渲染按
`内容像素 ÷ PPU` 缩放 quad（Part 2 的 DrawSprite 逻辑）：
- 普通精灵保持真实宽高比（非方形纹理不再被拉伸）。
- **动画每帧尺寸自动跟随内容**：站立帧高瘦、躺下帧矮宽——
  死亡动画的尺寸变化是渲染层免费获得的。
- 碰撞换算（像素→世界单位）共用同一 PPU，渲染与物理一套尺度。

## 6.4 动画事件与命令

事件在 `AnimationEditor` 时间线上添加（双击空白 + 右键编辑），
运行时触发 `CommandBus` 命令：

```text
event:attack_hit        # 触发自定义事件（战斗系统消费）
anim:play:{entity}:idle # 播放自己的 idle
anim:seek:Enemy_Bear:0.35
```

动画系统只负责"在正确时间发命令"，不关心语义——伤害结算、
音效、镜头震动都是 CommandBus 的消费者（Part 10 详讲）。

## 6.5 编辑器生产：分割器与动画编辑器

**SpriteSheetPickerPanel（分割器）** 是图集的第一生产工具：

1. 拖入纹理 → 调 Columns/Rows 切网格 → 点选格子（黄色框）。
2. **检测内容边界**：stb 解码纹理（CPU）→ 每格 alpha 包围盒 →
   自动填 trims（紫色框预览），可手动微调。
3. 每格可勾选**碰撞框**（绿色框），默认跟随内容框。
4. **Save As Sheet** 存 `.wtsheet`；**Replace Clip With Sequence**
   生成动画帧（自动写入 Sheet+CellIndex 引用）。
5. `Animation Editor` 的 **Save Clip As** 导出 `.wtanim` 资产。

**内容裁切解决了什么**：美术给的图集内容不在格子中央
（跳跃动画人物位置逐帧漂移）时，直接播放会跳动、露白边。
trim 后播放按内容框取 UV——内容自动对齐、无留白。

## 6.6 实例：主角 idle 动画从图集到播放

Sandbox 主角的 idle 动画（`side_combat_tuning.yaml` 的
`visuals.playerAnimations` 节）：

```yaml
visuals:
  playerAnimations:
    idle: { atlas: { sheet: ".../protag_idle_sheet.png",
                     cellWidth: 512, cellHeight: 512, columns: 8, startFrame: 0 },
            frameCount: 8, frameRate: 8.0, loop: true, renderScale: [1, 1],
            renderOffset: [0, 0.3398] }
```

对应资产 `protag_idle_sheet.wtsheet`（生成脚本自动产出）：

```yaml
texture: assets/vertical_slice/side_combat/sheets/runtime_characters/protag_idle_sheet.png
columns: 8
rows: 1
```

运行时链路（`SideCombatVisualService::EnsureAnimationClipLoaded`，
Part 10 详讲模块，这里看动画侧）：

1. 战斗模块首次需要 idle → 发现 `.wtsheet` 存在 →
   生成 `AnimationClip("idle")`，8 帧各带 `SpriteSheet + CellIndex = 0..7`。
2. 动画系统播放：`ApplyFrameToSprite` → `ResolveCell` 解析每帧
   （网格 → UV）→ 写入 `SpriteRendererComponent`。
3. 编辑器里打开分割器 Load Sheet → 改网格/加 trim → Save →
   250ms 后所有使用方热更新——**战斗动画在编辑时也能实时调**。

> 面试可讲：动画帧存"引用"而非"烘焙"——资产化让网格/裁切/碰撞
> 一处修改全链生效；`ResolveCell` 单点解析服务所有消费者；
> PPU 让渲染尺寸与碰撞共用同一尺度。
