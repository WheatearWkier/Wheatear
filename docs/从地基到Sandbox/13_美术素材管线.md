# Part 13 · 美术素材管线：四类素材如何进入资产系统

> 目标：理解 Sandbox 全部视觉素材的来源与接入方式——
> 程序化生成、AI 生图、动作视频抽帧、人工整理，
> 以及它们最终如何变成引擎资产（PNG + .wtsheet）。

## 13.1 四类素材来源总览

| 来源 | 内容 | 生产工具 | 产出形态 |
| --- | --- | --- | --- |
| 程序化生成 | 部分图标、VFX、UI 装饰 | 代码/脚本 | PNG（可直接用） |
| GPT-Image-2 | 立绘、背景、UI 皮肤 | 提示词批次生产 | PNG（人工整理） |
| 豆包/视频抽帧 | 角色动作序列 | 视频 → 抽帧 → 抠图 | 网格图集 PNG |
| 引擎工具 | 图集定义/裁切/碰撞框 | 编辑器分割器 | `.wtsheet` |

生产文档在 `docs/02_竖切版本/`（竖切美术资源生产指南/规范/批次包目录），
`AI生成素材批次/` 目录存放各批次生产包（提示词 + 规格 + 验收）。

## 13.2 程序化生成：可重建的素材

部分图标与 VFX 由代码生成（不依赖外部工具）：
- 技能图标底框、UI 装饰线、通用粒子。
- 优点：仓库内可重建、无版权顾虑；缺点：风格上限低——
  所以主要用在"功能性"素材（HUD 底框、图标边框），
  风格性素材（立绘/背景）走 AI。

## 13.3 AI 生图管线（GPT-Image-2）

竖切的立绘与背景走**批次生产**（`竖切美术资源批次包目录.md`）：

```
提示词锁定画风（Batch01A 小样）→ 验收 → 批量生成
→ 命名迁移（正式资源名 aoba_neutral.png 等）
→ 整理进 assets/vertical_slice/vn/portraits|backgrounds/
```

关键规范：
- **表情差分命名**：`aoba_{expression}.png`——直接对应 VN 的
  `{expression}` 模板（Part 9），表情切换零代码。
- **规格锁定**：每批记录尺寸/画风/验收标准，保证后续批次风格一致。
- 立绘是**逐文件 PNG**（非图集）——VN 表情差分按需加载，
  纹理缓存（Part 2）保证复用。

## 13.4 动作视频抽帧（豆包）

战斗角色动画是"豆包生成视频 → 抽帧 → 抠图 → 排布网格图集"：

```
视频 → 逐帧 PNG → 抠图（去背景）→ 排成 sheet（如 protag_idle_sheet.png
       8 帧 × 512×512）→ 在分割器里切网格并保存 .wtsheet → 运行时按格子取帧（Part 6）
```

- 图集命名与 tuning 对齐：`protag_idle_sheet.png` ↔
  `side_combat_tuning.yaml` 的 `idle` 条目（Part 10）。
- 抽帧后**必须抠图**（透明背景），否则 alpha 包围盒检测
  （分割器的"检测内容边界"）会把背景算进内容。
- `.wtsheet` 定义（网格参数/trim/碰撞框）由编辑器分割器产出；
  早期曾用一次性脚本 `Generate-SideCombatSheets.ps1` 批量迁移，
  产物已入库（`assets/vertical_slice/side_combat/sheets/`），脚本已删除——
  日常维护走分割器（13.5）。

## 13.5 引擎工具：分割器是素材管线的最后一站

所有素材最终在分割器（`SpriteSheetPickerPanel`，Part 6）过一遍：

1. 拖入 PNG → 切网格（Columns/Rows）。
2. **检测内容边界**（alpha 包围盒）→ trim 自动对齐
   （跳跃动画不跳、无留白）。
3. 每格配碰撞框（战斗角色按实际身体框）。
4. Save As Sheet → `.wtsheet` 资产。
5. ContentBrowser ▸ 展开格子/命名矩形 → 拖到场景/绑定动画。

**素材管线的终点是资产**：PNG 是"原料"，`.wtsheet` 是"定义"，
场景/动画只存引用（Part 4/6）——所以换图、调网格、改裁切
都是一处改动全链生效。
