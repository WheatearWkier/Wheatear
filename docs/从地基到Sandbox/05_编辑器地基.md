# Part 5 · 编辑器地基：面板体系、视口渲染与资源浏览器

> 目标：理解编辑器如何构建在引擎之上——ImGui 面板体系、DockSpace
> 布局、视口离屏渲染与交互拾取、资源浏览器的缓存与缩略图。
> 结尾用"在编辑器里摆一个精灵"的操作链路收束。

## 5.1 编辑器 = 引擎 + 一层 ImGui 面板

`WheatearEditor` 的入口还是 `main() → CreateApplication → Run`（Part 1），
差别只在挂载的 Layer。启动时先挂 `ModeSelectLayer`（**启动器**）：
选择 2D/3D 编辑模式 + **项目目录**（当前项目显示、`Projects/` 列表切换、
新建项目生成模板场景）——选定后 Push 对应的 `EditorLayer2D/3D` 并
Pop 自身（Part 4.7 的项目化机制）。

`EditorLayerBase : Layer` 持有全部面板与编辑器状态：

```cpp
std::unique_ptr<SceneHierarchyPanel> m_SceneHierarchyPanel;   // 层级树 + Inspector
std::unique_ptr<ContentBrowserPanel> m_ContentBrowserPanel;   // 资源浏览器
std::unique_ptr<AnimationEditorPanel> m_AnimationEditorPanel; // 动画编辑器
std::unique_ptr<SpriteSheetPickerPanel> m_SpriteSheetPickerPanel; // 图集分割器
std::unique_ptr<EditorHelpPanel> m_HelpPanel;                 // 帮助手册
std::unique_ptr<InputBindingsPanel> m_InputBindingsPanel;     // 输入绑定
// 其他独立工具窗口（WAO 动作编辑器 / 战斗调参 / 事件流程图等）按需从菜单打开
Ref<Scene> m_EditorScene;         // 正在编辑的场景（编辑系统集在跑）
Ref<Scene> m_ActiveScene;         // 当前激活场景（Edit = m_EditorScene，Play = 运行时副本）
EditorCamera m_EditorCamera;      // 轨道/飞行双模式相机
SceneState m_SceneState;          // Edit / Play
glm::vec2 m_ViewportSize;         // 视口面板尺寸
glm::vec2 m_ViewportBounds[2];    // 视口屏幕矩形（拾取用）
```

**面板都是普通类**，没有自己的窗口循环——每个面板实现
`OnImGuiRender()`，由 EditorLayer 每帧按固定顺序调用
（`EditorLayerBaseUI.cpp`）：

```cpp
ImGui::DockSpace(id, ...);            // ① 可停靠布局
UI_MenuBar();                         // ② 菜单栏
m_SceneHierarchyPanel->OnImGuiRender();   // ③ 层级 + Inspector
m_ContentBrowserPanel->OnImGuiRender();   // ④ 资源浏览器
m_AnimationEditorPanel->OnImGuiRender(ts);
m_SpriteSheetPickerPanel->OnImGuiRender();
UI_Viewport();                        // ⑤ 视口（场景渲染 + 交互）
```

ImGui 的 immediate mode 让面板代码非常直接：**每帧从头画一遍 UI，
状态（选中项、拖拽中）由面板自己持有**。没有"控件树 + 事件冒泡"，
面板之间通过 EditorLayer 的回调或面板公共方法通信
（如 ContentBrowser 双击场景 → `m_OnOpenScene` 回调 → EditorLayer 打开）。

## 5.2 浮动窗口：同一面板，可停靠可独立

`Editor/EditorFloatingWindow` 封装了 ImGui 窗口生命周期：

```cpp
if (EditorFloatingWindow::Begin("Sprite Sheet Picker", &m_Open, 0, {980, 700}))
{
    // ... 面板内容 ...
    EditorFloatingWindow::End();
}
```

配合 `EditorFloatingWindow::Dock(title)` 可以把浮动面板重新停回
DockSpace。这实现了"一个面板两种形态"：平时停靠在工作区，
需要专注时拖出成独立窗口（截图/多屏工作）。

## 5.2.1 当前源码里的工具注册

读编辑器源码时，先抓三条线：

1. **菜单怎么画**：`WheatearEditor/src/Editor/EditorLayerBaseUI.cpp`
   画主菜单。当前顶栏是
   `Scene / Edit / Run / UI / Window / Gameplay / Assets / Build / Diagnostics / App / Help`。
   `Build / Package Player + Editor` 的弹窗只选择 Startup Scene，
   GUI 打包固定 Release。
2. **玩法工具怎么注册**：`WheatearEditor/src/Modules/ModuleEditorBootstrap.cpp`
   调 `RegisterEditorTool` 注册 Event Script Editor、VN Script Editor、
   WAO Action Editor、Side/Turn/Arcade/Tactical Combat Tuning Editor、
   Progression Content Editor、Asset Alias / Manifest Editor 等。`Window`
   菜单和 `Gameplay` 菜单都会从这个注册表拿工具项。
3. **帮助文档怎么进编辑器**：`EditorHelpPanel` 启动时读取
   `WheatearEditor/Resources/Help/*.md`，按文件名排序显示；菜单入口是
   `Help / Editor Help`，快捷键是 `F1`。也就是说 Help 不是写死在 C++ 里，
   更新 Markdown 就会更新编辑器内手册。

组件注册也有两层：

- 核心组件在 `WheatearEditor/src/Editor/CoreEditorComponents.cpp` 注册，
  包括 Rendering、Lighting、Physics、Scripting & Audio 和 UI。
- 玩法组件在 `ModuleEditorBootstrap.cpp` 注册，包括 Visual Novel、
  Arcade Combat、Side Combat、Turn Combat、Tactical Combat。

这个拆法很适合新人理解"编辑器可扩展性"：新增一个玩法模块时，不应该把
菜单、组件绘制、运行时系统全部塞进一个巨大编辑器文件，而是让模块自己注册
面板和组件绘制函数。

## 5.3 视口：场景渲染到 framebuffer，再贴到 ImGui

`EditorLayerBaseUI_Viewport.cpp` 的 `UI_Viewport()` 是编辑器的心脏。
流程：

```cpp
// ① 视口尺寸变化 → 重建 framebuffer + 相机比例
if (m_Framebuffer && m_ActiveScene && w > 0 && h > 0)
{
    const auto& spec = m_Framebuffer->GetSpecification();
    if (spec.Width != w || spec.Height != h)
    {
        m_Framebuffer->Resize(w, h);
        m_EditorCamera.SetViewportSize(w, h);
        m_ActiveScene->OnViewportResize(w, h);
    }

    // ② 绑定离屏 framebuffer，渲染场景
    m_Framebuffer->Bind();
    RenderCommand::SetClearColor(...);
    RenderCommand::Clear();

    if (m_SceneState == SceneState::Edit)
        m_ActiveScene->OnUpdateEditor(Timestep(0), m_EditorCamera);  // 编辑系统集 + 渲染
    else
        m_ActiveScene->RenderWithSceneCamera(...);                    // Play：运行时相机
    m_Framebuffer->Unbind();
}

// ③ 把 framebuffer 的纹理贴到视口面板
const uint64_t texID = m_Framebuffer->GetColorAttachmentRendererID();
ImGui::Image(ImTextureID(texID), m_ViewportSize, {0,1}, {1,0});
```

三个关键点：

1. **编辑态每帧跑 `OnUpdateEditor`**：渲染发生在场景更新里
   （编辑器相机作为渲染相机传入），这与运行时 `OnUpdateRuntime`
   是同一套场景代码——Part 3 的"双系统集"在这里落到了渲染上。
2. **framebuffer 还带拾取附件**：`ClearAttachment(2, -1)` 清空
   EntityID 附件——Part 2 说过顶点带 `EntityID`，片元着色器把它
   写进第二个颜色附件。点击视口时读回该像素的 EntityID →
   就知道点中了哪个实体（`PickViewportEditorEntity`）。
3. **Play 模式用场景自己的相机**：`RenderWithSceneCamera` 找
   场景的 Primary Camera（VN 场景有 UI 相机）——所见即所得。

## 5.4 视口交互：gizmo、拖放、相机

- **Gizmo**：选中实体后 ImGuizmo 在视口叠加操纵杆
  （平移/旋转/缩放），拖动结束时把变换写回 `TransformComponent`
  并压入 `CommandHistory`（可撤销）。`m_GizmoEditEntity` +
  变换快照实现"拖动中不记录、松开才入栈"。
- **拖放资产**：ContentBrowser 拖出 `CONTENT_BROWSER_ITEM` payload
  （场景/预制体/UI 模板），视口 `AcceptDragDropPayload` 后存入
  `m_Deferred*Path`，帧尾 `ProcessDeferredViewportAssetDrop` 执行
  （打开场景 / 实例化预制体 / 创建精灵）——**延迟执行**避免在
  ImGui 回调里改场景（Part 3 的纪律再次出现）。
- **编辑器相机**：轨道/飞行双模式——按住 Alt：Alt+左键旋转、
  Alt+中键平移、Alt+右键缩放（滚轮也可缩放）；按住右键进入飞行模式
  （WASD/QE/Shift/Ctrl）；双击实体聚焦（`FrameEditorCameraOnEntity`）、
  双击视口空白对齐到场景主相机。

## 5.5 资源浏览器：ContentBrowser 的缓存与缩略图

`Panels/ContentBrowserPanel.cpp` 的几个设计：

1. **目录扫描缓存**（Part 4 讲过）：(目录, 搜索词) 键控 + 250ms 闸，
   大目录不再每帧文件 IO。
2. **离屏缩略图**：场景/预制体/动画等非图片资产进渲染队列，
   每帧渲染一个（`RenderThumbnail`：临时场景 → 128×128 FBO →
   `ReadPixelsRGBA` → 上传纹理 → 缓存）。**每帧只渲染一个**避免卡顿。
3. **格子条带**：`.wtsheet` 项右上角 ▸ 展开——规则格子 + 命名矩形
   的缩略图条带，每项可拖放（payload `path\ncell:N` / `path\nrect:Name`，
   Part 6 详讲）。
4. **右键菜单**：打开分割器 / 重命名 / 删除 / 复制路径，资产操作
   不离开浏览器。

补充：UI 创建菜单现在不只创建基础控件。Hierarchy 右键的 `UI / Templates`
可以生成 Titled Scroll Text、Paged Grid、Paged Inventory Grid、Skill Button、
Equipment Slot、Tooltip、Save Slot、Skill Tree Node、Combat Skill Slot 等
页面片段。基础创建菜单覆盖 Canvas、Panel、Image、Text、Button、Slider、
Checkbox、Progress Bar、Circle、Path、Pager、Scroll View；更多运行时 UI 行为
（UI Animator、Radial Cooldown、Skill Tree View、Page Item 等）通过
Inspector 的 Add Component 加到已有 UI 子控件上。

## 5.6 实例：在编辑器里摆一个精灵

1. 工具栏点"场景编辑器"或直接打开场景（双击 ContentBrowser 的
   `Example.wt`）。
2. 层级面板右键 → 新建实体（自动带 Tag/Transform）。
3. 拖一张 PNG 到 Inspector 的 SpriteRenderer 纹理槽
   （`BeginDragDropTarget` 接收 `CONTENT_BROWSER_ITEM`）→
   精灵出现在视口（编辑系统集 + 编辑器相机渲染）。
4. 选中实体 → gizmo 拖动定位 → 按 Ctrl+S 保存场景
   （`SceneSerializer::SerializeYaml` 写出 YAML）。
5. 运行器 `WheatearSandbox.exe` 打开同一场景——看到一样的画面。
   **编辑器与运行时共享同一份场景数据，这就是 Part 3 双系统集的
   最终价值。**
