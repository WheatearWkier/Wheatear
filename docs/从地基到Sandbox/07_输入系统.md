# Part 7 · 输入系统：事件、查询与动作绑定三层

> 目标：理解输入的三层结构（GLFW 事件 → 引擎查询 → 语义动作），
> 以及边沿检测状态机、鼠标负编码、命令注入这些设计细节。
> 结尾用"主角跳跃 `side.jump`"实例收束。

## 7.1 三层结构总览

```
第 1 层 · 事件        GLFW 回调 → 类型化事件 → EventBus 队列（Part 1）
第 2 层 · 查询        Input::IsKeyPressed / IsMouseButtonPressed（直接读状态位）
第 3 层 · 语义动作    InputBindingService::IsActionDown("side.jump")
                      —— 动作名 ↔ 键位映射（可重映射、可注入）
```

为什么需要三层？

- **第 1 层**处理"外部输入 → 内部状态"：GLFW 数字码翻译成
  `WT_KEY_*` 枚举，事件入队帧首统一派发（Part 1 讲过）。
- **第 2 层**是裸查询：`WindowsInput` 在事件处理时写状态位
  （按下的键集合、鼠标位置/增量），玩法代码随时可查。
- **第 3 层**是语义层：玩法不关心"哪个键"，只关心"什么动作"。
  键盘、手柄、脚本注入都能产生同一个动作。

## 7.2 查询层：Input 与状态位

`Input/Input.h`：

```cpp
static bool IsKeyPressed(int keycode);        // 当前帧该键是否按下
static bool IsMouseButtonPressed(int button); // 鼠标按钮
static float GetMouseDeltaX();                // 自上次 EndFrame 的鼠标位移
static void EndFrame();                       // 帧末滚动状态
```

`EndFrame` 在 `Application::Run` 里每帧调用（Part 1 的主循环③）。
它做两件事：把"本帧按下"滚动为"上帧按下"（供边沿检测），
并更新鼠标增量基线。**没有 EndFrame，按住按键会被误判为
每帧都"刚按下"**。

## 7.3 动作层：InputBindingService

`Input/InputBindingService.h` 的接口：

```cpp
// Edge queries (IsActionPressed / IsActionReleased) are frame-based:
// call EndFrame() once per frame from the application loop, then any
// consumer sees consistent per-frame results.

static bool IsActionDown(const std::string& actionId);      // 当前是否按住
static bool IsActionPressed(const std::string& actionId);   // 上升沿：本帧刚按下
static void InjectActionPress(const std::string& actionId); // 命令注入：脚本/AI 模拟输入
static void EndFrame();                                     // 状态机收尾
static int  ButtonToMouseBinding(int mouseButton) { return -(mouseButton + 1); } // 负编码
```

### 7.3.1 动作绑定

每个动作（`side.jump`、`vn.advance`、`side.basic`...）映射到一组
键位。默认绑定在 `Config/UserSettings.cpp`：

```cpp
AddBinding(settings, "side.jump",    { WT_KEY_SPACE, WT_KEY_UP });
AddBinding(settings, "vn.advance",   { WT_KEY_SPACE, WT_KEY_ENTER, WT_KEY_RIGHT });
```

- 键位可以是键盘键、鼠标按钮（**负编码**：`-1` = 左键、`-2` = 右键，
  与键码正数空间不冲突，一个枚举空间装两类输入）。
- 玩家可在编辑器的 **Input Bindings 面板**重映射，配置持久化到
  UserSettings——玩法代码零改动。

### 7.3.2 边沿状态机

`IsActionPressed` 的语义：本帧按住 && 上一帧没按住。实现是
每帧 `EndFrame` 里把"当前按下集合"滚动成"上次按下集合"，
查询时两个集合比对。Part 1 的 VN 例子（`!PreviousAdvancePressed`）
就是这个机制的消费者——**按一下只触发一次**。

### 7.3.3 命令注入

`InjectActionPress` 让**非输入来源**也能产生动作：
- 战斗 AI 想触发"跳跃"→ 注入 `side.jump`（复用人输入链路）。
- 事件脚本（`.wts`）想模拟玩家操作 → 注入动作。
- 自动化测试/回放 → 注入动作序列。

这保证了"所有玩法入口统一"：无论输入来自键盘还是 AI，
玩法代码看到的都是 `IsActionDown("side.jump")`。

## 7.4 实例：主角跳跃的输入链路

玩家在战斗中按空格（或上方向键），主角起跳：

```
GLFW 键盘回调 → KeyPressedEvent(WT_KEY_SPACE) 入队
      ↓ 帧首派发
WindowsInput 写状态位：空格 = 按下
InputBindingService 动作状态：side.jump = 按下
      ↓ InputBindingService::EndFrame（帧末滚动）
下一帧 SideCombat 控制系统：
    if (InputBindingService::IsActionPressed("side.jump") && 可以跳)
        → 起跳逻辑（跳跃速度、二段跳、土狼时间...）
```

- 玩法代码里**没有任何键码**——`side.jump` 重映射成别的键，
  战斗系统不需要重编。
- 如果以后接入手柄：手柄回调 → 同一个动作状态，战斗系统依旧零改动。
- 录制回放：`InjectActionPress("side.jump")` 即可重放一次跳跃。
