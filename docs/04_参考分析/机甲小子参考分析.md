## 机甲小子空连机制参考分析

### 0. 分析目的

本文档用于记录对本地目录 `D:/games/jijia` 中《机甲小子 / 机甲旋风》资源结构和战斗动作线索的分析结果。

目标不是复制原游戏代码或素材，而是抽取它“击飞后空中平 A、缓慢下坠、持续追击”的手感规律，用来改进 Wheatear 当前 `SideCombat` 的空连与断限玩法。

### 2. 主逻辑线索

主 SWF 的 ABC 字符串池能看到以下战斗相关命名：

| 命名 | 推测职责 |
| --- | --- |
| `GameKeyboard`、`CKey`、`keyControl` | 自定义输入层。 |
| `RoleActionManger`、`CAction`、`ActionConstant` | 自定义动作状态机。 |
| `RATiao`、`RAZou`、`RAPao`、`RANGong` | 跳、走、跑、攻击等角色动作。 |
| `CAbeida` | 被打 / 受击动作。 |
| `CASkillOne`、`CABulletOne`、`CABulletSelect` | 技能和子弹类动作。 |
| `hitTestByBullet`、`hitTestByRoleX`、`hitTestByRoleY` | 自写命中检测，按 X/Y 和对象关系判断。 |
| `jumpFlag`、`jumpLimit`、`jumpFrame` | 跳跃状态、跳跃限制和跳跃帧控制。 |

结论：

- 它的手感核心不是物理引擎，而是自定义输入、动作状态机、时间轴动画和命中盒。
- 浮空与受击很可能由动作状态和命中效果驱动，而不是完全交给重力模拟。
- 这和 Wheatear 当前 `SideCombat` 的方向一致：用自定义空中高度、受击状态、命中框和调参表控制手感。

### 4. 帧长参考

按 30 FPS 粗略估算：

| 动作 | 男角色帧段 | 女角色帧段 | 手感含义 |
| --- | --- | --- | --- |
| 地面攻击 1 | 约 20 帧 | 约 20 帧 | 普攻第一段节奏中等。 |
| 地面攻击 2 | 约 18 帧 | 约 17 帧 | 第二段略快，方便连段。 |
| 地面攻击 3 | 约 27 帧 | 约 20 帧 | 可作为重一点的衔接或小收尾。 |
| 普通跳击 | 男约 6 帧 | 女约 16 + 12 帧 | 空中攻击短、轻、可重复。 |
| 跳冲 | 男约 4 帧 | 女约 21 + 8 帧 | 空中追击 / 位移派生独立于跳跃。 |

这些帧长说明：

- 空中平 A 爽，不是因为单次攻击很重，而是因为短动作、快恢复、命中后给滞空和敌人受控。
- 地面攻击承担起手和节奏，空中攻击承担续连和维持。
- 空中追击 / 跳冲是另一个动作，不应该和普通跳跃键混在一起。

### 5. 对 Wheatear 的设计结论

#### 5.1 键位职责更新

新的设计决策：

| 输入 | 新职责 |
| --- | --- |
| `A / D` | 左右推进。 |
| `W / S` | 纵深移动；其中 `S` 可作为下方向修饰键。 |
| `J` | 地面普攻；空中平 A / 跳斩。 |
| `K` | 一段跳。`K` 不再负责击飞。 |
| `S + J` | 地面上挑 / 浮空启动。参考机甲小子的组合输入感。 |
| `U` | 当前竖切魔法弹，后续可以迁移到正式技能槽。 |
| `I` | 当前竖切支援。 |
| `L` | 当前竖切断限调试 / 后期断限追击。 |

这一改动的核心是：

- 跳跃就是跳跃，不附带攻击和击飞职责。
- 击飞由明确的启动技承担，比如 `S + J`、特定主动技能、支援技能或断限成功。
- 断限成功本身应有一次“再挑起 / 再击飞”效果，用来把快坠落的敌人重新送入可连状态。

#### 5.2 空中平 A 规则

Wheatear 应把空中 `J` 做成核心战斗动词：

- 空中 `J` 命中后，主角获得短暂滞空。
- 敌人进入受击 / 浮空受控状态，不能继续普通攻击。
- 每次命中让主角和目标都轻微下落一点，形成“能连很久但不断下沉”的手感。
- 空中 `J` 可以有 2 段轻量循环，例如 `air_basic_1`、`air_basic_2`。
- 空挥不应给明显滞空，避免玩家靠空挥逃课。

推荐初始参数：

| 参数 | 建议 |
| --- | --- |
| 空中普攻前摇 | 0.03-0.05 秒 |
| 命中框持续 | 0.10-0.16 秒 |
| 后摇 | 0.08-0.14 秒 |
| 命中硬直 | 0.32-0.48 秒 |
| 主角命中滞空 | 0.08-0.16 秒或小向上冲量 |
| 每次命中下坠步进 | 0.04-0.10 高度单位 |
| 常规空中平 A 次数 | 3-5 次，断限后刷新 |

#### 5.3 上挑 / 击飞规则

`S + J` 应承担早期浮空启动：

```text
地面 J 普攻 1-2 -> S+J 上挑 -> K 跳跃追上 -> 空中 J 平 A -> U 魔法补 hit -> 落地
```

设计重点：

- `S + J` 是固定派生 / 指令普攻，不一定占用主动技能槽。
- 上挑前摇要比空中平 A 稍长，让玩家感到它是启动技。
- 上挑命中后应给主角一个追跳窗口，方便 `K` 起跳接空中平 A。
- Boss 正常状态只短浮空，破防状态和断限状态才明显可持续空连。

#### 5.4 断限规则更新

断限不是普通二段跳，也不是纯 UI 计时成功。

断限成功应做三件事：

1. 刷新一次跳跃和空中动作次数。
2. 给主角短暂停滞或小上冲，让玩家有时间接下一招。
3. 对目标产生一次明确的再击飞 / 再挑起效果，把快落地的敌人重新抬回空连节奏。

推荐表现：

```text
低空快坠落 -> L 断限成功 -> 魔法阵碎裂 / 时间停顿 -> 目标被再挑起 -> K 追跳 -> 空中 J 继续平 A
```

### 6. 当前 Wheatear 差距

当前工程和文档仍保留旧输入口径：

| 当前内容 | 差距 |
| --- | --- |
| `SideCombatSystem.cpp` 中 `Space` 是跳跃，`K` 是 launcher。 | 需要把 `K` 改为跳跃，把 `S+J` / 下方向 + 普攻改为 launcher。 |
| `side_combat_tuning.yaml` 中 `launcher.input: K`，`air_chase.input: 空中 K`。 | 需要改为组合输入和技能标签，不再绑定 `K`。 |
| 战斗 HUD 有 `SC_SkillSlot_K` 和 `icon_skill_launcher_slash.png`。 | 需要改成跳跃图标或把上挑放到指令提示，不再作为 K 技能槽。 |
| 多份文档写了 `K 上挑 / 空中追斩`。 | 需要统一更新为 `K 跳跃`、`S+J 上挑`。 |

### 7. 建议落地顺序

1. 输入层先重构为可配置动作映射：

```yaml
input:
  jump: [K, Space]
  basicAttack: [J, MouseLeft]
  launcher: [S+J, Down+J]
  magic: [U]
  support: [I]
  breakLimit: [L]
```

2. `SideCombatSystem` 中把“固定动作”和“主动技能”分开：

- 固定动作：移动、跳跃、普攻、空中平 A、`S+J` 上挑、闪避。
- 主动技能：魔法、支援、后续剑技、融合技、奥义。
- 机制动作：断限追击、空界连锁。

3. YAML 中新增指令技字段：

```yaml
commandMoves:
  launcher:
    displayName: 裂空挑斩
    input: S+J
    attackIds: [launcher]
    comboRole: 地面浮空启动
```

4. 战斗 HUD 更新：

- `J` 显示普攻 / 空中平 A，不占主要技能栏。
- `K` 显示跳跃，不占主要技能栏。
- `S+J` 作为前期击飞指令提示或教程提示，不占主要技能栏。
- `U/I/L` 等技能继续显示冷却。

5. 再调空中平 A 和断限参数：

- 降低空中平 A 单次伤害和保护增长。
- 提高命中硬直和命中滞空。
- 增加命中后的轻微下坠。
- 断限成功附带再击飞。

### 8. 一句话结论

机甲小子的空连手感可以概括为：

```text
明确的地面启动技 -> 独立空中平 A 动作 -> 命中才滞空 -> 敌人受控不反击 -> 每次攻击缓慢下坠 -> 特定追击 / 断限重新抬高
```

Wheatear 后续应按这个模型升级 `SideCombat`：`K` 回归一段跳，`S+J` 做上挑，空中 `J` 做可重复轻空连，断限成功做再击飞和空中资源刷新。
### 9. v0.10 工程落地补充

本轮把参考内容落到竖切战斗工程中，重点不是照搬《机甲小子》的数值，而是吸收它的动作游戏成熟感：

- `K / Space` 固定为跳跃，`J / MouseLeft` 固定为普攻；二者不进入主动技能栏。
- `S + J` 作为地面上挑，空中 `S + J` 作为空中追斩，承担“起浮空 / 补高度 / 接空连”的职责。
- 角色与敌人从单张 sprite 改为动作 clip：`idle / run / jump / fall / hit / dead / attack` 都可以按 YAML 绑定序列帧。
- 每个攻击动作增加 `swingSound / hitSound / hitPause / cameraShake`，命中反馈从“只扣血”升级为“挥击音、命中音、停顿、镜头轻震、受击动画”同步发生。
- 空中普攻保持“命中滞空但缓慢下落”的规则，`air_basic.attackerAirImpulse`、`attackerAirFallStep`、`targetAirFallStep` 是后续试玩调手感的核心参数。
- 敌人被浮空或受击硬直时不会继续行动，未完成的敌人攻击会被取消；以后只有显式配置的霸体技、反击技、空中反击技可以例外。

物理策略维持自定义 kinematic：地面横向和纵深移动由速度与加速度控制，空中高度由 `RuntimeAirHeight` 与自定义 gravity 控制。通用物理引擎可以用于障碍碰撞、调试可视化和未来场景机关，但不应该直接决定跳跃、浮空、受击硬直和连击滞空。

## 机甲小子 UI 布局参考分析

### 0. 分析目的

本文档记录对本地目录 `D:/games/jijia` 中《机甲小子 / 机甲旋风》UI SWF 资源的布局解析结果。

目标不是复制原游戏素材、代码或界面，而是提炼它在战斗 HUD、装备背包、技能面板、角色属性、强化和仓库页面上的信息摆放规律，用来指导 Wheatear 竖切 UI 的下一轮打磨。

### 1. 分析方法

资源大多是 Adobe AIR / Flash 的 `CWS` 压缩 SWF。解析方式如下：

- 解压 SWF 数据。
- 读取舞台尺寸和帧率。
- 读取 `ExportAssets` / `SymbolClass`，找到导出的主面板类。
- 递归读取 `PlaceObject` / `PlaceObject2` 显示列表。
- 解析每个实例的矩阵，得到坐标、缩放、层级和实例名。

结论：这些 UI 的舞台大多是 `960x600`，左上角为原点。下面表格中的坐标均按这个坐标系记录。

部分控件出现负坐标，不代表错误，通常是遮罩、滑动面板、运行时弹出层或鼠标跟随提示框。

### 8. 对 Wheatear UI 的直接建议

#### 8.1 战斗 HUD

- 采用 `960x600` 参考布局，按 Canvas 自适应缩放到目标分辨率。
- 左上：生命、魔剑能量、断限槽。
- 顶中：Boss 血条、Boss 保护槽。
- 底左：消耗品 / 临时道具槽。
- 底中：主动技能槽，必须支持图标、冷却灰罩、倒计时数字、按键标签。
- 底右：装备、技能树、支援、背包、系统图标按钮。
- 技能栏上方：Buff / Debuff 小图标。

#### 8.2 据点与管理页面

- 背包、仓库、图鉴、邮件附件统一走 `PagedInventoryGrid`。
- 背包页默认 `4x5`，仓库 / 图鉴默认 `6x5`，商店默认 `3x4` 商品卡。
- 页签在上方，主要内容在左/中，详情和操作在右，下方放货币与确认按钮。
- 悬浮 tooltip 负责短说明；点击详情面板负责完整说明和操作。

#### 8.3 编辑器组件需求

为了让这些布局能在 WheatearEditor 中复用，后续 UI 组件最好继续补齐：

| 组件 | 需要能力 |
| --- | --- |
| `UIPagedGridComponent` | 行列数、格子间距、起点、分页、连续填充 |
| `UISkillSlotComponent` | 图标、冷却灰罩、倒计时、按键标签、禁用覆盖 |
| `UIBuffRowComponent` | 横向小图标列表、层数、剩余时间、tooltip |
| `UITooltipComponent` | 悬浮跟随、边界避让、延迟出现 |
| `UITabGroupComponent` | 页签互斥、高亮、禁用、切页命令 |
| `UIComparePanelComponent` | 当前属性、升级后属性、变化值高亮 |

### 9. 当前结论

机甲小子的 UI 不是靠大量说明文字堆出来的，而是靠固定信息区域、图标按钮、格子网格、页签和短提示组织出来的。

Wheatear 后续应模仿这种结构感：

- 重要操作优先图标化。
- 说明文字只在需要时出现。
- 背包、仓库、商店、技能配置都用统一可复用控件。
- 战斗 HUD 保持底部一条操作带，避免遮挡战斗主体。
- 坐标和布局不要硬编码在游戏逻辑里，而是暴露到 Canvas / UI 控件参数，允许编辑器微调。
